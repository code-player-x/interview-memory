## 2. C# 中值类型、引用类型与按值/按引用传参有什么区别？

> 原题 ID：`q1498`

**高频程度**：★★★★

**考察点**：区分类型分类与参数传递方式，避免把“引用类型”误说成“按引用传参”。

**回答框架**：

1) 值类型变量直接保存值，引用类型变量保存对象引用
2) C# 参数默认按值传递，引用类型参数复制的是引用值
3) ref、out、in 才是按引用传递变量
4) 装箱会创建对象，但不等同于把原变量按引用传递

**参考回答**：

C# 需要分清两个互相独立的维度：变量的类型是值类型还是引用类型，以及参数是按值还是按引用传递。

值类型变量通常直接保存值，例如数值类型、枚举和 struct；把它赋给另一个变量或按值传参时，会复制这个值。引用类型变量保存的是对对象的引用，例如 class、数组、delegate 和 string；按值传递引用类型参数时，复制的是引用值，因此形参和实参最初指向同一个对象。通过形参修改该对象的内容，调用方通常可见；但把形参重新赋给另一个对象，不会改变调用方变量保存的引用。

`ref`、`out` 和 `in` 才表示按引用传递变量本身：`ref` 允许读写已有变量，`out` 要求被调用方赋值，`in` 提供只读引用。装箱是把值类型值复制进一个新的对象，不等于把原值类型变量改成按引用传递。判断行为时应分别回答“复制的是什么值”和“被调用方能否重新绑定调用方变量”。

**常见追问**：为什么把 List<T> 按值传入方法后可以修改列表内容，却不能通过重新赋值替换调用方的变量？

**核验资料**：[C# parameter passing](https://learn.microsoft.com/dotnet/csharp/language-reference/keywords/method-parameters)

## 5. Python 类继承中的 MRO 和 super() 如何工作？

> 原题 ID：`q2588`

**高频程度**：★★★

**考察点**：考察对「class类的继承呢？」的掌握，重点看能否讲清：继承是让子类获得父类属性与方法的机制，本质是“is-a”关系与代码复用

**回答框架**：

继承是让子类获得父类属性与方法的机制，本质是“is-a”关系与代码复用；1) 基本写法：；class Animal:；def __init__(self, name): self.name = name；def speak(self): return '...'；class Dog(Animal):

**参考回答**：

Python 中 class 继承通过 MRO（C3 线性化）决定属性查找顺序，子类可复用/重写父类，并用 super() 协作调用。

继承是让子类获得父类属性与方法的机制，本质是“is-a”关系与代码复用。

1) 基本写法： class Animal: def __init__(self, name): self.name = name def speak(self): return '...' class Dog(Animal): def speak(self): return self.name + ' 汪汪' Dog('旺财').speak() # 旺财 汪汪
2) 属性查找：实例 __dict__ -> 类 __dict__ -> 按 MRO 依次找父类。MRO 由 C3 线性化算法生成，可用 Dog.__mro__ 或 Dog.mro() 查看。
3) super()：不是“父类”，而是“MRO 中当前类的下一个类”。在多重继承/菱形继承中，super() 保证每个父类只初始化一次，形成协作式调用链。 class A: def __init__(self): print('A'); super().__init__() class B(A): def __init__(self): print('B'); super().__init__() class C(A): def __init__(self): print('C'); super().__init__() class D(B, C): def __init__(self): print('D'); super().__init__() D() # D B C A，MRO 为 D,B,C,A,object
4) 方法重写与扩展：子类同名方法覆盖父类；想保留父类逻辑用 super().method()。
5) 多态：调用方只依赖父类接口，运行时根据实例真实类型分派，实现“同一接口，不同行为”。
6) 抽象基类：abc.ABC + @abstractmethod 强制子类实现，适合定义接口。
7) 适用场景：领域建模（Dog is Animal）、框架插件/模板方法、复用通用逻辑。组合优于继承：若只是“has-a”或行为可插拔，优先组合，避免继承层次过深导致脆弱基类问题。

**常见追问**：如何避免「1) 把 super() 理解成“调用父类”，在多重继承下会错」？ 「它按 MRO 找下一个类」在真实项目中应如何规避？

**参考回答**：

代码由语法结构（词法/语法单元）与语义逻辑（数据、控制、抽象）两层组成，最终被编译/解释为机器可执行的指令序列。

从不同视角看，代码的组成可以拆成三层：

1) 字符层（词法）：源代码本质是字符流，先被词法分析器（Lexer）切成 Token，比如关键字、标识符、字面量、运算符、分隔符。例如 `int a = 1 + 2;` 会被切成 `int`、`a`、`=`、`1`、`+`、`2`、`;`。
2) 语法层（结构）：Token 按语法规则组成抽象语法树（AST）。AST 是代码的结构化表示，节点代表表达式、语句、函数、类等。例如赋值语句是一个节点，左边是变量，右边是加法表达式。
3) 语义层（逻辑）：在 AST 上做名称解析、类型检查、作用域分析，再生成中间表示（IR）或字节码，最终由编译器/解释器/虚拟机变成机器指令或直接执行。

通俗类比：代码像一篇文章。字符是字母，Token 是单词，语法是造句规则，AST 是句子结构图，语义是文章要表达的意思，编译/解释是把文章翻译成机器能听懂的“母语”。 从编程语言本身看，代码通常由这些基本构件组成：

- 数据：变量、常量、字面量、数据类型；
- 运算：算术、逻辑、比较、位运算；
- 控制流：顺序、分支（if/switch）、循环（for/while）；
- 抽象：函数/方法、类/对象、模块/包、接口；
- 组织：注释、命名空间、导入导出、构建配置。 不同语言只是这些构件的语法糖和组合方式不同，底层都要落到“数据 + 控制 + 抽象”这三件事上。

**常见追问**：如何避免「1) 只回答“变量、函数、类”这种表面清单，没有讲清代码从字符到执行的层次」？ 「2) 把“代码组成”和“程序组成”混为一谈，忽略源码文本与运行时状态的区别」在真实项目中应如何规避？

这道题本质是问：如何从零构建可维护、可检索、可迭代的个人知识体系，而不是单纯收集资料；核心是『以输出倒逼输入』的结构化沉淀方法。

面试官问这个，通常不是要你背八股，而是考察你的学习方法论和工程化思维。构建个人知识体系可以类比为搭一个后端服务：

1) 需求分析（明确目标）：先想清楚知识体系服务谁、解决什么问题。是应对面试、日常开发查漏，还是长期技术成长？目标不同，结构完全不同。面试导向就按『计算机基础 + 语言 + 框架 + 中间件 + 系统设计 + 项目』分域；成长导向则按『领域树 + 问题驱动』组织。
2) 数据建模（确定结构）：不要一上来就建几十个文件夹。推荐『MOC（Map of Content）+ 原子笔记』两层结构。原子笔记一个概念一篇，例如『MySQL 索引为什么用 B+ 树』；MOC 是索引页，例如『MySQL 知识地图』，用链接把原子笔记串起来。这类似数据库的『事实表 + 维度表』，避免信息孤岛。
3) 存储与检索（选工具）：工具只是载体，别陷入工具焦虑。Obsidian/Logseq 适合双链和本地 Markdown；Notion/语雀适合协作和展示；GitHub 仓库适合代码化、可版本管理。关键指标是：能否全文检索、能否双向链接、能否导出为纯文本，避免被平台锁定。
4) 写入流程（持续迭代）：采用『费曼式写作』——每学一个点，用自己的话写清楚『是什么、为什么、怎么用、坑在哪』。例如学 Redis 持久化，不要抄 RDB/AOF 定义，而是写『RDB 是快照，恢复快但可能丢数据；AOF 是日志，丢数据少但文件大；生产常用混合持久化』。
5) 复习与输出（闭环）：知识体系不是写完就完，要定期回顾、重构、删除过时内容。可以配合间隔重复（Anki）或每周写一篇总结。面试前不是重新学，而是快速过 MOC，查漏补缺。

通俗类比：知识体系像一座图书馆，原子笔记是书，MOC 是分类索引，双链是书之间的参考文献，检索是借书系统。没有索引的图书馆只是仓库，没有输出的知识只是收藏。

## 8. 量子计算机的原理？

> 原题 ID：`q3301`

**高频程度**：★★★

**考察点**：考察对「量子计算机的原理 √（附加）」的掌握，重点看能否讲清：经典比特只能处于0或1，而量子比特（qubit）可处于|0>和|1>的叠加态：|ψ>=α|0>+β|1>，其中α、β为复数概率幅，满足|α|²+|β|²=1

**回答框架**：

经典比特只能处于0或1，而量子比特（qubit）可处于|0>和|1>的叠加态：|ψ>=α|0>+β|1>，其中α、β为复数概率幅，满足|α|²+|β|²=1；n个量子比特可同时表示2^n个基态的叠加，这是量子并行性的来源；但量子计算并非简单“同时试所有答案”：测量会以概率|α_i|²坍缩到某个基态，因此必须通过量子门和干涉，让错误答案的概率幅相消、正确答案的概率幅增强；核心资源包括：叠加、纠缠（多个qubit状态不可分解，如(|00>+|11>)/√2）、干涉、量子门（酉变换，可逆）、测量；典型算法：Shor算法利用量子傅里叶变换求周期，实现大数分解指数加速；Grover算法通过振幅放大，在N个无序项中平方级加速搜索

**参考回答**：

量子计算机利用量子比特的叠加与纠缠，通过量子门操控概率幅，使特定算法在测量前同时探索大量路径，从而在部分问题上获得指数或平方级加速。

经典比特只能处于0或1，而量子比特（qubit）可处于|0>和|1>的叠加态：|ψ>=α|0>+β|1>，其中α、β为复数概率幅，满足|α|²+|β|²=1。n个量子比特可同时表示2^n个基态的叠加，这是量子并行性的来源。但量子计算并非简单“同时试所有答案”：测量会以概率|α_i|²坍缩到某个基态，因此必须通过量子门和干涉，让错误答案的概率幅相消、正确答案的概率幅增强。

核心资源包括：叠加、纠缠（多个qubit状态不可分解，如(|00>+|11>)/√2）、干涉、量子门（酉变换，可逆）、测量。

- 典型算法：Shor算法利用量子傅里叶变换求周期，实现大数分解指数加速；
- Grover算法通过振幅放大，在N个无序项中平方级加速搜索；
- 量子模拟可高效模拟量子系统。

类比：经典计算像一枚硬币只能正面或反面；量子计算像旋转中的硬币，同时包含正反概率，但最终拍停时只能看到一面。

适用场景：大数分解、无序搜索、量子化学/材料模拟、组合优化、采样等；对普通业务逻辑、文本处理并无优势。
