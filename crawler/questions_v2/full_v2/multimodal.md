## 2. LLaVA 的视觉—语言对齐与指令微调分别训练哪些模块？MLP Projector 与 Q-Former 如何取舍？

> 原题 ID：`q1159`

**高频程度**：★★★★★

**考察点**：考察 LLaVA 分阶段训练中冻结策略的变化，以及 MLP Projector 和 Q-Former 在信息保留、压缩与计算成本上的取舍。

**回答框架**：

1) 区分预训练对齐阶段与视觉指令微调阶段；2) 第一阶段通常冻结视觉编码器和 LLM、训练 projector；3) 原始 LLaVA 第二阶段通常更新 projector 与 LLM、保持视觉编码器冻结；4) MLP 保留更多视觉 token 且结构简单；5) Q-Former 用可学习 query 压缩视觉信息。

**参考回答**：

LLaVA 不能概括成“始终冻结 LLM、只训练 Projector”。以原始 LLaVA 的两阶段训练为例：第一阶段做视觉—语言特征对齐，通常冻结视觉编码器和 LLM，只训练线性 projector；第二阶段做视觉指令微调，通常仍冻结视觉编码器，但更新 projector 和 LLM。具体冻结策略会随版本和训练方案变化，回答时应明确所指阶段。

MLP projector 直接把视觉编码器的 patch 特征映射到 LLM embedding 空间，结构简单、训练和推理开销低，也保留较多视觉 token。它的代价是长高分辨率输入会产生较多 token，把筛选和融合压力交给 LLM。Q-Former 用少量可学习 query 通过交叉注意力从视觉特征中抽取固定数量表示，能够压缩 token、隔离模态，但增加模块复杂度和计算，也可能因固定 query 数形成信息瓶颈。

因此两者没有脱离任务的绝对优劣。需要细粒度 OCR、定位或高分辨率理解时，要关注压缩是否丢细节；更关注延迟、实现简单和大规模数据训练时，MLP 可能更合适。最终应同时比较任务质量、视觉 token 数、首 token 延迟、吞吐和显存。

## 4. 请解释 CLIP 的对比学习训练原理（对称 InfoNCE 与温度系数），并说明 SigLIP 用 sigmoid 替代 softmax 解决了什么问题？

> 原题 ID：`q1161`

**高频程度**：★★★★★

**考察点**：考察 CLIP 对称 InfoNCE、可学习温度，以及 SigLIP 逐对 sigmoid loss 的区别与工程含义。

**回答框架**：

1) 图文双塔与批内正负样本；2) 对称 InfoNCE；3) logit scale 与温度的方向；4) SigLIP 的逐对 sigmoid loss 和可学习 bias；5) batch 与跨设备归一化的取舍。

**参考回答**：

CLIP 用图像编码器和文本编码器把配对图文映射到同一归一化向量空间。一个 batch 中，匹配图文是正样本，其余组合是批内负样本；训练分别做“图找文”和“文找图”的交叉熵，再对两个方向取平均，这就是对称 InfoNCE。

相似度 logits 通常写成 `exp(logit_scale) * cosine_similarity`，等价于余弦相似度除以温度 τ。尺度越大（温度越小），softmax 分布越尖锐。实现中限制的是指数化后的 logit scale 上限，而不是把温度本身简单裁剪到同一区间。

SigLIP 不再对整行或整列做 softmax，而是把每个图文对独立看成正负二分类，使用 sigmoid loss，并加入可学习 bias 缓解负样本数量远多于正样本的问题。这样不需要跨设备收集全局 softmax 归一化项，在较小 batch 下也能有效训练、扩展更方便；但它并不意味着 batch 大小完全无关，也不能据此断言单机必须或天然能使用 32k 以上 batch。

## 11. 实现 InfoNCE Loss（基于 CLIP 的对比损失）？

> 原题 ID：`q1488`

**高频程度**：★★★★

**考察点**：实现 InfoNCE Loss（基于 CLIP 的对。

**回答框架**：

1) InfoNCE 是把对比学习建模为“从 N 个候选中挑出正样本”的交叉熵损失，CLIP 用它把匹配的图像-文本对拉近、不匹配的推远
2) InfoNCE 的核心思想：给定一个锚点（anchor），在包含 1 个正样本和 N-1 个负样本的候选集合中，让模型学会识别哪个是正样本

**参考回答**：

InfoNCE 是把对比学习建模为“从 N 个候选中挑出正样本”的交叉熵损失，CLIP 用它把匹配的图像-文本对拉近、不匹配的推远。

InfoNCE 的核心思想：给定一个锚点（anchor），在包含 1 个正样本和 N-1 个负样本的候选集合中，让模型学会识别哪个是正样本。它等价于一个 N 分类的 softmax 交叉熵，其中 logits 是锚点与各候选的相似度除以温度 τ。

公式（以 CLIP 的图像到文本方向为例）：
L_i = -log( exp(sim(z_i^I, z_i^T)/τ) / Σ_{j=1}^{N} exp(sim(z_i^I, z_j^T)/τ) )
其中 z 是归一化后的 embedding，sim 通常用点积（即余弦相似度），τ 是可学习或固定的温度系数。

CLIP 的完整损失是对称的：图像→文本和文本→图像两个方向各算一次 InfoNCE，再取平均。
L = (L_i2t + L_t2i) / 2

为什么有效：
1) 把对比学习变成分类问题，负样本天然来自 batch 内其他样本，无需额外采样；
2) 温度 τ 控制分布的尖锐程度，τ 越小越关注难负样本；
3) 归一化 embedding + 点积，使相似度有界，训练稳定。

通俗类比：就像一场“找对象”考试，给一张图，候选是 batch 里所有文本，只有配对的文本是正确答案。模型要在一堆干扰项中把正确文本的分数推到最高。

实现要点（PyTorch 伪代码）：
1) 图像/文本分别过编码器，得到 I [N, d]、T [N, d]；
2) 各自 L2 归一化；
3) logits = I @ T.T / τ，形状 [N, N]；
4) 对角线是正样本，标签为 arange(N)；
5) loss_i2t = cross_entropy(logits, labels)，loss_t2i = cross_entropy(logits.T, labels)，总损失取平均。

适用场景：多模态对齐（CLIP）、自监督表示学习（SimCLR、MoCo）、检索、句子嵌入（如 Sentence-BERT 的对比训练）。

4. 识别层排查。裁剪检测框单独送识别，看是检测错还是识别错。常见原因：字体/语种不匹配、字符集缺失、竖排/弯曲文本、低分辨率、训练数据与真实分布偏差。对策：补充真实场景标注、换 CRNN/SVTR/TrOCR 等模型、加语言模型/词典约束、对关键字段做正则校验。

5. 后处理与结构化排查。OCR 出字对但字段抽取错，问题在规则/模板/LLM 抽取。检查正则、关键词、坐标关系、表格结构还原。对策：加字段级校验（金额格式、日期合法性、校验位）、用版面分析+关系抽取，或 LLM 做纠错但要有置信度兜底。

6. 工程与数据闭环。检查预处理与训练不一致（如训练用灰度、线上用彩色）、版本回滚、并发/超时导致截断。建立 badcase 回流和自动评测，按版式/来源分桶看指标，避免整体平均掩盖局部崩溃。

我的决策：先花半天做分层评测和可视化，确认瓶颈在检测还是识别；若检测召回低优先修检测，若识别 CER 高优先补数据/换模型；结构化错则加规则校验。复盘：早期直接换大模型但没定位，浪费算力；后来用分桶指标发现某类票据倾斜严重，加透视矫正后字段准确率提升明显。

**参考回答**：

直播/视频理解是把时序多模态信号转成结构化语义，VLM 是用视觉编码器+LLM 做跨模态对齐与生成，直播场景核心难点在实时性、长时序和弱标注。

一、概念定义。视频理解指对视频做分类、检测、检索、问答、摘要等任务，输入是 T 帧图像+音频+文本（弹幕/标题/ASR），输出是标签、片段、描述或答案。VLM（Vision-Language Model）是把视觉编码器（ViT/CLIP/SigLIP）产出的视觉 token 经投影层（MLP/Q-Former）对齐到 LLM 词向量空间，再让 LLM 自回归生成文本，代表有 CLIP、BLIP-2、LLaVA、Qwen-VL、InternVL、GPT-4o。直播内容理解是视频理解的一个子集，特点是流式、无剪辑、超长（小时级）、强实时、弹幕/礼物等互动信号丰富。

在TTS工程中，音频处理与离散化主要有两条路线：

1) 两阶段（传统/主流）：文本→声学模型→梅尔频谱（连续帧，如80维、帧移10ms）→声码器（HiFi-GAN、WaveNet）→波形。这里音频不直接离散成token，而是用连续梅尔谱作为中间表示。优点是声码器可独立优化，音质好；缺点是梅尔谱有信息损失，且两阶段误差累积。

2) 端到端离散token路线（近年主流，如VALL-E、Tortoise、Bark）：先用神经音频编解码器把波形编码成离散token，再让TTS模型自回归/非自回归预测token，最后用解码器还原波形。

离散化核心是神经音频编解码器，典型结构：编码器（卷积下采样，如从24kHz降到50Hz帧率）→量化器→解码器。量化器常用RVQ（Residual Vector Quantization）：
- 第一层量化器把编码器输出向量量化到码本中最近邻，得到token1；
- 计算残差（原向量-量化向量），第二层再量化残差，得到token2；
- 重复N层（如8层），每层码本大小通常1024。
这样每帧音频得到N个token（如8个），帧率约50Hz，即每秒400个token。

工程上关键点：
- 码本大小与层数权衡：码本越大、层数越多，重建质量越高，但token序列越长，TTS模型建模难度和推理成本越高。
- 训练目标：重构损失（L1/L2）+ 量化损失（码本承诺损失）+ 对抗损失（GAN判别器）+ 特征匹配损失，常用SoundStream/EnCodec方案。
- 离散token的TTS建模：VALL-E用两阶段：先预测第一层码本（粗粒度），再以第一层为条件预测其余层（细粒度），类似分层自回归。
- 推理时：TTS模型输出token序列，送入解码器（如EnCodec decoder）还原波形，可流式。

例子：EnCodec在24kHz音频上，帧率75Hz，8层RVQ，每层1024码本，每秒600个token。VALL-E用类似配置，但帧率50Hz。

踩坑：
- 梅尔谱离散化（如k-means）效果差，因为梅尔谱本身连续且高维，直接聚类会丢失细节。
- RVQ层数太多导致token序列过长，自回归TTS推理慢且易错。
- 码本坍塌：部分码本向量很少被使用，需用EMA更新或重启策略。
- 训练解码器时，若直接用TTS预测的token（而非真实token）做输入，会有暴露偏差，需 scheduled sampling 或 teacher forcing 调整。

## 19. Stable Diffusion 中的潜在扩散模型（LDM）原理是什么？

> 原题 ID：`q3732`

**高频程度**：★★★

**考察点**：Stable Diffusion 中的潜在扩散模型（。

**回答框架**：

1) LDM 的核心是先用 VAE 把图像压缩到低维潜在空间，再在潜在空间上做扩散/去噪，最后解码回像素空间，从而在几乎不损失生成质量的前提下把计算量降低一到两个数量级
2) 传统扩散模型（DDPM）直接在像素空间操作：一张 512×512×3 的图有约 78 万个维度，每一步去噪都要让 U-Net 在这个高维空间上跑一遍，训练和采样都极慢

4) VAE 用重建损失 + KL 正则 + 感知损失/对抗损失训练，保证解码回来的图在感知上几乎无损
5) 潜在扩散阶段：在 z 上训练扩散模型（通常是 U-Net）

**参考回答**：

LDM 的核心是先用 VAE 把图像压缩到低维潜在空间，再在潜在空间上做扩散/去噪，最后解码回像素空间，从而在几乎不损失生成质量的前提下把计算量降低一到两个数量级。

传统扩散模型（DDPM）直接在像素空间操作：一张 512×512×3 的图有约 78 万个维度，每一步去噪都要让 U-Net 在这个高维空间上跑一遍，训练和采样都极慢。LDM（Rombach 等，CVPR 2022）的思路是“先压缩、再扩散”：

1) 感知压缩阶段：训练一个 VAE（编码器 E + 解码器 D），把图像 x 编码成潜在表示 z = E(x)，维度比如 64×64×4，即下采样 8 倍、通道压到 4，空间维度缩小 64 倍。VAE 用重建损失 + KL 正则 + 感知损失/对抗损失训练，保证解码回来的图在感知上几乎无损。

2) 潜在扩散阶段：在 z 上训练扩散模型（通常是 U-Net）。前向过程按同样公式加噪 z_t = sqrt(ᾱ_t)·z_0 + sqrt(1-ᾱ_t)·ε，反向过程学习预测噪声 ε_θ(z_t, t, c)，条件 c 可以是文本（通过 CLIP/T5 编码后做 cross-attention）、类别、掩码等。因为 z 的维度远小于 x，U-Net 的算力主要花在低维空间，训练和采样都快得多。

3) 采样与解码：从纯高斯噪声 z_T 出发，用 DDIM/PLMS/DPM-Solver 等采样器迭代去噪得到 z_0，再经解码器 x̂ = D(z_0) 还原成图像。

通俗类比：像素空间扩散像“直接在 4K 原片上逐帧修图”，又慢又费显存；LDM 像“先把片子压成小样（缩略图）在缩略图上修，修完再放大回原片”。因为图像的大部分信息是冗余的，真正的语义结构在低维流形上就能表达，所以在潜在空间去噪等价于在语义层面去噪。

适用场景：高分辨率文生图（Stable Diffusion 系列）、图像编辑/Inpainting、超分、视频生成（如 SVD、部分视频扩散模型也沿用该范式）。关键超参是下采样因子 f（SD 用 f=8）和潜在通道数（SD 用 4），f 越大越快但重建细节损失越大，需要权衡。

**常见追问**：如何避免「1) 误以为 LLaVA 也用了 Q-Former——LLaVA 是纯 MLP 投影，没有 query 机制」？ 「2) 误以为 BLIP-2 的 ViT 和 LLM 都训练了——BLIP-2 两阶段都冻结 ViT 和 LLM，只训 Q-Former 和投影层」在真实项目中应如何规避？

## 28. 无分类器引导（CFG）是如何工作的？

> 原题 ID：`q3733`

**高频程度**：★★★

**考察点**：考察对「无分类器引导（CFG）是如何工作的」的掌握，重点看能否讲清：无分类器引导（Classifier-Free Guidance, CFG）由 Ho & Salimans 在 2022 年提出

**回答框架**：

无分类器引导（Classifier-Free Guidance, CFG）由 Ho & Salimans 在 2022 年提出，核心思想是：不需要额外训练一个分类器，而是让同一个扩散模型（或流匹配模型）同时学会“有条件生成”和“无条件生成”，然后在采样时把两者的预测结果做线性外推；原理：设模型 εθ(x_t, t, c) 是条件噪声预测，εθ(x_t, t, ∅) 是把条件 c 置空（如空文本、dropout 条件）后的无条件预测；CFG 的引导预测为：；ε̃ = εθ(x_t, t, ∅) + w * (εθ(x_t, t, c) - εθ(x_t, t, ∅))；其中 w 是引导系数（guidance scale）；当 w=1 时退化为普通条件生成

**参考回答**：

CFG 通过在采样时同时计算有条件与无条件噪声预测，并用引导系数 w 外推二者之差，从而在生成质量与多样性之间做权衡。

无分类器引导（Classifier-Free Guidance, CFG）由 Ho & Salimans 在 2022 年提出，核心思想是：不需要额外训练一个分类器，而是让同一个扩散模型（或流匹配模型）同时学会“有条件生成”和“无条件生成”，然后在采样时把两者的预测结果做线性外推。 原理：设模型 εθ(x_t, t, c) 是条件噪声预测，εθ(x_t, t, ∅) 是把条件 c 置空（如空文本、dropout 条件）后的无条件预测。CFG 的引导预测为： ε̃ = εθ(x_t, t, ∅) + w * (εθ(x_t, t, c) - εθ(x_t, t, ∅)) 其中 w 是引导系数（guidance scale）。当 w=1 时退化为普通条件生成；w>1 时强化条件信号；w=0 时完全无条件。 为什么有效：从贝叶斯角度看，条件生成需要 score ∇log p(x|c) = ∇log p(x) + ∇log p(c|x)。CFG 用 (ε_cond - ε_uncond) 近似 ∇log p(c|x) 的方向，相当于隐式地做了一个“分类器引导”，但分类器由生成模型自身提供，避免了额外训练分类器及其在噪声数据上训练不稳定的问题。 训练阶段：通常以一定概率（如 10%）把条件 c 替换为空条件 ∅，让模型同时具备无条件预测能力。推理阶段再按上式组合。 通俗类比：想象一个画家既会“自由发挥”（无条件），也会“按题作画”（有条件）。CFG 就是让画家先画一版自由发挥的底稿，再对比“按题作画”与“自由发挥”的差异，然后把这个差异放大 w 倍叠加到底稿上——放大越多，越贴合题目，但可能失去自然感。 适用场景：文本到图像（Stable Diffusion、DALL·E 2）、文本到视频、语音合成、分子生成等条件生成任务。w 通常取 5~15（图像），太小则条件不生效，太大则过饱和、伪影、多样性下降。

**常见追问**：如何避免「误以为 CFG 需要额外训练一个分类器——那是 classifier guidance，CFG 不需要。」？ 「误以为 w 越大越好——w 过大会导致过饱和、伪影、模式坍塌、多样性下降。」在真实项目中应如何规避？
