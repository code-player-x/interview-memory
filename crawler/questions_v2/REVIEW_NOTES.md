# full_v2 第二轮修订记录

本轮基于整体检查结果修改，基线为 671 题，修订后为 632 题。没有重新编号原题 ID；Markdown 中的展示序号随分类内容重新生成。

## 修改范围

- 合并 39 道语义重复或范围高度重叠的题目。
- 完整改写 69 道题的题干、考点、框架、回答与追问；另对 11 道题做题干或框架修订。
- 将 8 道题迁入更合适的分类，集中长期记忆、权限控制、线上评测和多模态等考点。
- 清理重复的“加分点/常见雷区”附录和模板式考点。修改前有 278 个答案带“加分点”，修订后不再保留该模板标签。
- 清除“常见追问：追问：”、机械追问和截断句。无法恢复为有独立价值完整问题的追问不展示，人工改写的题目补充了具体追问。
- 答案总字符数从 454,839 降至 311,953；最长答案由超过 3,400 字符降至 1,489 字符。字符数只用于检查冗长程度，不是质量评分。

## 数据恢复与维护

本轮发生变化的 409 条原始记录保存在 [second_pass_originals.jsonl](./review_archive/second_pass_originals.jsonl)，包含原分类、完整原记录和最终去向。39 道被合并题也在其中，可按 ID 回查或恢复。

日常修改入口仍为 `authored/*.jsonl`。本轮人工修订的题目另有 `reviewed_full_v2.py` 覆盖表；修改这些 ID 时应同时更新对应覆盖项，否则再次生成会应用已登记的修订。旧的第一轮覆盖项位于 `curate_full_v2.py`。生成命令：

```bash
python3 crawler/questions_v2/curate_full_v2.py
```

归档不是当前题库输入，不参与题数、索引或重复检测。

## 验证结果

- 632 个 ID、632 个标题全部唯一，必填教学字段非空。
- 10 个分类的 JSONL、Markdown 题序/ID/题数及 INDEX 完全一致。
- 39 个合并源已移出当前题库，所有合并目标存在；8 个迁移目标正确。
- 模板追问、重复前缀、截断追问和截断框架残留为零。
- 本轮修改和合并记录均可从归档回查，能够重建 671 题的本轮基线。
- 连续运行生成器后，源数据、Markdown、索引与归档的字节哈希不变。
- Python 语法、CRLF 行尾和尾随空格检查通过。

语义去重采用候选相似度检查加人工判断；相似度低不构成没有重复的证明。上述验证说明本轮列出的缺陷已处理，不代表所有产品行为在未来版本中永久不变。

## 第三至第五轮全库整理（历史记录）

上面的“第二轮”是当时 10 个 AI 分类的历史记录，不能把其中的 632 题或后续合并时的 3,318 题当作当前题库数量。跨设备内容已统一进入同一个确定性生成器；这一阶段的源题库覆盖 25 个分类，生成结果为 **2,884** 道题。

本轮对全部分类进行了内容边界、题干独立性、分类和已确认事实的复核，主要处理如下：

- 合并或移除 38 道重复、残缺或无法独立作答的题；原始记录保留在归档中。
- 将一批“承接上文”“宣传语”“聊天片段”式题干改为自包含问题；不能可靠恢复对象的题直接移除。
- 修正高风险技术表述：Linux 外部中断/异常/软件陷入与 hardirq/softirq 的边界，梯度检查点的性能取舍，GPT 与 Encoder-Decoder 的架构区别，Go GC 与 Green Tea 的事实边界，以及 JavaScript 装箱、Redis 大 Key、索引设计等。
- 把 Go GC、RAG、Agent、前端流式传输、算法和行为面试等条目迁到实际所属分类。
- 继续把范围高度重合的题压缩为一题：例如可靠 UDP、Redis Stream 选型、消息积压、Agent 与 Workflow、LoRA、Self-Attention、Vue 2/3、Adam/AdamW、ZeRO 和三类 Transformer 架构。

维护入口与生成方式：

- 当前审核规则由 [reviewed_full_v2.py](./reviewed_full_v2.py) 与 [reviewed_extra_v2.py](./reviewed_extra_v2.py) 共同维护；前者保留 AI 第二轮规则，后者管理后续全库规则。
- [curate_full_v2.py](./curate_full_v2.py) 读取全部 25 个 `authored/*.jsonl`，应用两套规则后重写 JSONL、Markdown、索引和归档。
- 原始条目及其去向位于 [second_pass_originals.jsonl](./review_archive/second_pass_originals.jsonl) 与 [third_pass_extra_originals.jsonl](./review_archive/third_pass_extra_originals.jsonl)，不参与当前题数与展示。

当时验证结果：25 个分类的 JSONL、Markdown 题序/ID 和 INDEX 完全一致；2,884 个 ID 与标题唯一，必填教学字段非空，答案没有完全重复；已登记的合并源不再出现在当时库、目标题均存在且分类正确。连续运行生成器后的源文件、Markdown、INDEX 与归档字节哈希不变。

## 第六轮独立复核（历史记录）

在上一轮 2,920 题基线上，又按“题干自包含、一个题只承载一个主考点、技术表述可核验”的标准进行了一次独立复核，当时为 **2,884** 题。

- 删除 12 道多主题拼接、导航/营销文案或缺少对象的残缺题；删除原因均编码在 `reviewed_extra_v2.py`，原记录保留在归档。
- 合并 24 道与现有规范题范围实质重叠的条目，包括上下文压缩、工具定义、RAG 分块、注意力、ZeRO、Cookie/Token、Redis 性能和意图澄清等；每个源题的规范目标题明确登记。
- 将一批错分条目迁入 Agent、RAG、评测、前端、预训练、安全、系统设计等实际主题域，并将保留题的题干、考察点、框架、回答和追问改为独立可答的内容。
- 修正高风险表述：`curl -N` 只关闭客户端输出缓冲而非保证端到端实时；点积注意力与加法注意力并非笼统等价；tokenizer 迁移不必然要求全量重训 embedding/输出层；DeepSeek-V3/R1 的架构、训练与后训练结论以其技术报告为条件。

本轮的规则仍在 [reviewed_extra_v2.py](./reviewed_extra_v2.py) 中，重新运行 `python3 crawler/questions_v2/curate_full_v2.py` 即可重建当时的 JSONL、Markdown、索引和归档。只有当 `questions_v2` 批次没有学习记录关联时，才允许用 `--replace` 覆盖同步。
