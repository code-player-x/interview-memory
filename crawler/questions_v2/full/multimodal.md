## 2. LLaVA 为什么冻结 LLM、只训练 Projector？而为什么现在很多强模型（如 Qwen、LLaMA-3 级别）

> **高频程度**：★★☆☆☆　|　**原题 ID**：`q1159`　|　**标签**：`多模态与前沿架构` `冻结LLM省成本显存` `Projector参数少` `MLP更简单稳定更快` `Q-Former有信息瓶颈` `取决于LLM能力与数据量`

**考察点**：【由分类/标签推断】多模态 方向，重点考察 多模态与前沿架构、冻结LLM省成本显存、Projector参数少、MLP更简单稳定更快 的理解与工程落地、边界场景的掌握。

**回答框架**：冻结LLM省成本显存；Projector参数少

**参考回答**
冻结LLM省成本显存；Projector参数少

LLaVA 冻结 LLM（数十亿参数）只训练 Projector，是因为 LLM 本身已有强语言能力，全量微调成本极高、显存占用大，而 Projector 只有几百万参数，训练快、风险小，能在资源有限时让 LLM「读懂」视觉 token。后来很多模型用回 MLP 而非 Q-Former，是因为当 LLM 能力足够强、且训练数据量足够大时，简单的 MLP 就能学到好的映射，且训练更稳定、推理更快；Q-Former 虽能通过可学习 query 做「按需提取」，但多一层计算开销，且固定数量的 query（如 32 个）存在信息瓶颈，可能丢失细粒度信息。所以没有绝对优劣，取决于 LLM 能力、数据规模与场景。

**加分点**

MLP更简单稳定更快；Q-Former有信息瓶颈；取决于LLM能力与数据量

## 3. Q-Former 在多模态模型中起什么作用？它有什么优缺点，还有哪些视觉 token 压缩方案？

> **高频程度**：★★☆☆☆　|　**原题 ID**：`q1160`　|　**标签**：`多模态与前沿架构` `可学习query加cross-attention` `视觉token压缩` `降输入长度与成本` `损失细粒度信息` `pooling/token merging/AnyRes`

**考察点**：【由分类/标签推断】多模态 方向，重点考察 多模态与前沿架构、可学习query加cross-attention、视觉token压缩、降输入长度与成本 的理解与工程落地、边界场景的掌握。

**回答框架**：可学习query加cross-attention；视觉token压缩

**参考回答**
可学习query加cross-attention；视觉token压缩

Q-Former 是一组可学习的 query token（如 32 个），通过 cross-attention 从冻结的视觉编码器输出中「按需提取」出固定数量的视觉摘要 token 送给 LLM，相当于一个视觉信息抽取器，把大量 patch token 压缩成少量 token，降低 LLM 输入长度与推理成本。优点是减少视觉 token、降低显存与首 token 延迟、提升多图输入能力；缺点是固定 query 数量会损失细粒度信息（小目标、文字、局部细节）。其他压缩方案包括：用更大的 patch size 减少 patch 数、对视觉特征做 pooling、token merging、多尺度选择性输入，以及 LLaVA-NeXT 的 AnyRes 动态分辨率切片。

**加分点**

降输入长度与成本；损失细粒度信息；pooling/token merging/AnyRes

## 4. 请解释 CLIP 的对比学习训练原理（对称 InfoNCE 与温度系数），并说明 SigLIP 用 sigmoid 替代

> **高频程度**：★★☆☆☆　|　**原题 ID**：`q1161`　|　**标签**：`多模态与前沿架构` `双塔对比学习` `对称InfoNCE` `温度系数可学习` `SigLIP用sigmoid` `摆脱batch依赖` `大batch可单机训`

**考察点**：【由分类/标签推断】多模态 方向，重点考察 多模态与前沿架构、双塔对比学习、对称InfoNCE、温度系数可学习 的理解与工程落地、边界场景的掌握。

**回答框架**：双塔对比学习；对称InfoNCE

**参考回答**
双塔对比学习；对称InfoNCE

CLIP 用海量图文对训练两个编码器，让匹配的图文向量在共享空间里靠近、不匹配的远离。其损失是对称的 InfoNCE：对图像到文本、文本到图像两个方向各做 N 路 softmax 平均，温度系数 τ 可学习（logit_scale 被 clip 在 0.01~100 之间），用于调节相似度分布的锐度。SigLIP 改用 sigmoid 二分类损失，对 N×N 相似度矩阵中每一项独立做 binary cross-entropy，摆脱了对 batch 内其他样本的 softmax 归一化依赖，因此对 batch size 不再线性敏感，单机也能用大 batch（如 32k+）训练，并引入可学习 bias 修正初期的负样本主导问题。

**加分点**

温度系数可学习；SigLIP用sigmoid；摆脱batch依赖；大batch可单机训

## 5. 多模态大模型为什么容易出现「幻觉」（如图片里没有猫却说有猫、数错人数），有哪些缓解手段？

> **高频程度**：★★☆☆☆　|　**原题 ID**：`q1162`　|　**标签**：`多模态与前沿架构` `幻觉不等于文本幻觉更难检` `分辨率不足` `token过度压缩` `LLM先验太强` `高分辨率加事实核查` `结合专用工具`

**考察点**：【由分类/标签推断】多模态 方向，重点考察 多模态与前沿架构、幻觉不等于文本幻觉更难检、分辨率不足、token过度压缩 的理解与工程落地、边界场景的掌握。

**回答框架**：幻觉不等于文本幻觉更难检；分辨率不足

**参考回答**
幻觉不等于文本幻觉更难检；分辨率不足

VLM 幻觉（编造图像中不存在的内容）比纯文本幻觉更难检测，成因主要有四：视觉分辨率不足导致细节丢失；视觉 token 被过度压缩丢失局部信息；LLM 先验太强，即使视觉证据不足也会补全「合理答案」；训练数据偏差使模型形成错误偏见。缓解手段包括：提高输入分辨率（AnyRes 切片）、引入高分辨率编码器、做多模态事实核查与对比解码、用 RLHF/对齐增强忠实度、对 OCR/小目标/图表等高可靠场景结合专用检测与版面分析工具，而非完全依赖端到端 VLM。

**加分点**

token过度压缩；LLM先验太强；高分辨率加事实核查；结合专用工具

**回答框架**：避免通用知识重复存储；共享专家承载公共知识

**参考回答**
避免通用知识重复存储；共享专家承载公共知识

在纯路由专家中，所有专家都要重复存储「所有 token 都需要的通用知识」，造成参数冗余。共享专家的动机是：设少量始终激活的「通才」专家处理公共知识，路由专家只需专注差异化、专业化内容，避免重复、提升参数效率。DeepSeekMoE 进一步把标准专家拆成更细粒度的小单元（如 160 个小专家、每次激活 6 个），提升路由灵活性与专业化程度，再配合共享专家承载通用信息，并用 MLA 压缩 KV Cache，最终以 671B 总参、37B 激活参达到极高性价比，是 MoE 工程化的标杆。

**加分点**

细粒度专家提升灵活性；路由专家专注差异化；配合MLA压缩KV；高性价比

## 7. 什么是旋转位置编码（RoPE）？相比绝对位置编码它有什么优势，为什么它更擅长处理长上下文与位置外推？

> **高频程度**：★★☆☆☆　|　**原题 ID**：`q1167`　|　**标签**：`多模态与前沿架构` `旋转矩阵编码位置` `Q/K施加旋转` `注意力只依赖相对位置` `优于绝对位置编码` `外推友好(NTK/YaRN)` `Llama/Qwen/DeepSeek采用`

**考察点**：【由分类/标签推断】多模态 方向，重点考察 多模态与前沿架构、旋转矩阵编码位置、Q/K施加旋转、注意力只依赖相对位置 的理解与工程落地、边界场景的掌握。

**回答框架**：旋转矩阵编码位置；Q/K施加旋转

**参考回答**
旋转矩阵编码位置；Q/K施加旋转

RoPE（Rotary Position Embedding）由 Su et al. 2021 提出，核心思想是把位置信息编码成「旋转」操作：对查询 Q 和键 K 的每一对维度施加一个与位置 m 相关的旋转矩阵，使注意力得分只依赖 token 间的相对位置（旋转矩阵的乘积性质让内积等价于相对位移的旋转）。相比绝对位置编码（如正弦或可学习 embedding 直接加到 token 上），RoPE 的优势是：位置信息融入 Q/K 本身、天然表达相对位置、与外推友好——配合 NTK-by-parts / YaRN / LongRoPE 等缩放策略可在不重训的情况下把上下文窗口外推数倍。因此 Llama、Qwen、DeepSeek 等主流模型都用 RoPE。

**加分点**

注意力只依赖相对位置；优于绝对位置编码；外推友好(NTK/YaRN)；Llama/Qwen/DeepSeek采用

## 8. MoE 在推理部署阶段有哪些工程挑战？为什么显存由「总参数」而非「激活参数」决定，All-to-All 通信为何在小 b

> **高频程度**：★★☆☆☆　|　**原题 ID**：`q1168`　|　**标签**：`多模态与前沿架构` `显存由总参数决定` `所有专家常驻` `算术强度低/GPU等数据` `All-to-All小batch成瓶颈` `EP加TP混合` `Offloading与量化`

**考察点**：【由分类/标签推断】多模态 方向，重点考察 多模态与前沿架构、显存由总参数决定、所有专家常驻、算术强度低/GPU等数据 的理解与工程落地、边界场景的掌握。

**回答框架**：显存由总参数决定；所有专家常驻

**参考回答**
显存由总参数决定；所有专家常驻

MoE 推理有三个层面挑战。一是显存：所有专家权重必须常驻显存（因为 Router 可能随时激活任意专家），所以显存由总参数决定而非激活参数——Mixtral 8×7B 总参约 47B 必须全加载，超出单张 80GB 卡，需跨卡分片。二是算术强度低：每个专家只处理分配给它的少数 token，权重加载后计算量小，GPU 大量时间花在等显存取数而非计算，硬件利用率低；路由不均会加剧。三是通信：分布式推理每个生成步都要跨 GPU 做 All-to-All 把 token 发给对应专家，自回归解码 batch 小，通信延迟占比高、易成瓶颈。工程优化包括专家并行（EP）+ 张量并行（TP）混合、GroupedGEMM 批处理、计算通信重叠、专家卸载（Offloading）、量化压缩。

**加分点**

算术强度低/GPU等数据；All-to-All小batch成瓶颈；EP加TP混合；Offloading与量化

LLaVA拼接式简单；Flamingo冻结主干加融合层

**加分点**

Perceiver Resampler压缩；Gated Cross-Attention注入；交错图文/少样本；优劣对比

## 16. CLIP 的原理与损失函数设计，对比学习的核心思想

> **高频程度**：★★☆☆☆　|　**原题 ID**：`q1486`　|　**标签**：`概念基础` `juejin` `zhihu`

**考察点**：【由分类/标签推断】多模态 方向，重点考察 概念基础、juejin、zhihu 的理解与工程落地、边界场景的掌握。

**回答框架**：CLIP 用双塔分别编码图像和文本，通过对比学习在 batch 内拉近匹配图文对…

**参考回答**
CLIP 用双塔分别编码图像和文本，通过对比学习在 batch 内拉近匹配图文对、推远不匹配对，核心是 InfoNCE 对称损失。

CLIP（Contrastive Language-Image Pre-training）是 OpenAI 提出的图文预训练模型。原理：图像塔（ViT 或 ResNet）把图片编码成向量 I_i，文本塔（Transformer）把配对的文本编码成向量 T_j，两个塔各自接一个线性投影到同一维度 d，并做 L2 归一化，使向量落在单位球面上，点积即余弦相似度。对一个 batch 的 N 个图文对，计算 N×N 相似度矩阵 S，S_ij = I_i·T_j / τ，其中 τ 是可学习的温度系数。对角线是正样本对，其余是负样本。损失函数是 InfoNCE 的对称形式：图像到文本方向，对每一行做 softmax 交叉熵，目标为对角线；文本到图像方向，对每一列做同样操作；两者取平均。公式为 L = (CE(S, y) + CE(S^T, y)) / 2，y 为 [0..N-1]。直观理解：把匹配文本当作图像的正确类别，在一个 batch 内做 N 类分类。对比学习核心思想：不依赖人工标签，而是让模型学会‘相似样本靠近、不相似样本远离’；正样本来自同一图文对，负样本来自 batch 内其他样本，因此 batch 越大负样本越多，效果越好（CLIP 用了 32768 的 batch）。温度 τ 控制 softmax 的尖锐程度，可学习让模型自适应调整。适用场景：零样本分类（把类别名写成 prompt 如 'a photo of a dog'，算图像与各文本的相似度取最大）、图文检索、作为多模态模型的视觉编码器（如 LLaVA、Stable Diffusion 的文本编码器）。

**加分点**

1) 损失本质是 N 路分类的交叉熵，等价于最大化正样本互信息下界（InfoNCE），可联系 CPC、MoCo。2) 对称损失很重要：只用 image-to-text 会让文本塔梯度弱，双向能平衡两塔。3) 温度 τ 可学习且初始化为 0.07（logit_scale=log(1/0.07)），训练中会变大，说明模型学会降低对难负样本的惩罚。4) 负样本并非全负：batch 内可能有语义相同的其他图文对，造成假负样本，这是 CLIP 的已知噪声来源。5) 工程上相似度矩阵在 GPU 上做 all-gather 可跨卡扩大负样本，但要注意梯度。6) 与 SigLIP 对比：SigLIP 用 sigmoid 二分类损失替代 softmax，不需要全局归一化，小 batch 更稳。

**雷区**

1) 误以为 CLIP 是生成模型或能直接输出 caption，它只做匹配打分，不能生成文本。2) 把对比学习说成监督分类，忽略其自监督/弱监督本质。3) 忘记 L2 归一化和温度系数，导致相似度尺度不对。4) 只写单向损失，忽略对称性。5) 认为 batch 大小无关紧要，实际上负样本数量直接决定效果。6) 混淆 CLIP 的零样本能力来源：不是微调，而是用自然语言 prompt 做类别描述。7) 把 τ 当成固定超参，忽略其可学习性。

## 17. 实现 InfoNCE Loss（基于 CLIP 的对比损失）

> **高频程度**：★★☆☆☆　|　**原题 ID**：`q1488`　|　**标签**：`概念基础` `juejin` `zhihu`

**考察点**：【由分类/标签推断】多模态 方向，重点考察 概念基础、juejin、zhihu 的理解与工程落地、边界场景的掌握。

**回答框架**：InfoNCE 是把对比学习建模为“从 N 个候选中挑出正样本”的交叉熵损失，C…

**参考回答**
InfoNCE 是把对比学习建模为“从 N 个候选中挑出正样本”的交叉熵损失，CLIP 用它把匹配的图像-文本对拉近、不匹配的推远。

InfoNCE 的核心思想：给定一个锚点（anchor），在包含 1 个正样本和 N-1 个负样本的候选集合中，让模型学会识别哪个是正样本。它等价于一个 N 分类的 softmax 交叉熵，其中 logits 是锚点与各候选的相似度除以温度 τ。

公式（以 CLIP 的图像到文本方向为例）：
L_i = -log( exp(sim(z_i^I, z_i^T)/τ) / Σ_{j=1}^{N} exp(sim(z_i^I, z_j^T)/τ) )
其中 z 是归一化后的 embedding，sim 通常用点积（即余弦相似度），τ 是可学习或固定的温度系数。

CLIP 的完整损失是对称的：图像→文本和文本→图像两个方向各算一次 InfoNCE，再取平均。
L = (L_i2t + L_t2i) / 2

为什么有效：
1) 把对比学习变成分类问题，负样本天然来自 batch 内其他样本，无需额外采样；
2) 温度 τ 控制分布的尖锐程度，τ 越小越关注难负样本；
3) 归一化 embedding + 点积，使相似度有界，训练稳定。

通俗类比：就像一场“找对象”考试，给一张图，候选是 batch 里所有文本，只有配对的文本是正确答案。模型要在一堆干扰项中把正确文本的分数推到最高。

实现要点（PyTorch 伪代码）：
1) 图像/文本分别过编码器，得到 I [N, d]、T [N, d]；
2) 各自 L2 归一化；
3) logits = I @ T.T / τ，形状 [N, N]；
4) 对角线是正样本，标签为 arange(N)；
5) loss_i2t = cross_entropy(logits, labels)，loss_t2i = cross_entropy(logits.T, labels)，总损失取平均。

适用场景：多模态对齐（CLIP）、自监督表示学习（SimCLR、MoCo）、检索、句子嵌入（如 Sentence-BERT 的对比训练）。

**加分点**

1) 温度 τ 的实现：CLIP 用可学习参数 logit_scale = log(1/τ)，并 clamp 最大值（如 100），防止训练中 τ 过小导致梯度爆炸。
2) 负样本数量：batch 越大，负样本越多，InfoNCE 的下界越紧，效果通常越好；但显存受限，可用梯度累积、MoCo 式队列或跨设备 all_gather 扩大负样本。
3) 与互信息的关系：InfoNCE 是互信息 I(x;c) 的下界（Oord et al. 2018），最小化它等价于最大化互信息下界。
4) 数值稳定：cross_entropy 内部用 logsumexp，避免直接 exp 溢出；若手写需减去 max。
5) 对称损失的重要性：只做单向会导致表示偏向某一模态，CLIP 实验证明对称更好。
6) 难负样本挖掘：τ 小或使用 hard negative 可提升，但太强会崩塌，需权衡。

**雷区**

1) 忘记 L2 归一化：不归一化时点积受向量模长影响，温度失去意义，训练不稳定。
2) 忘记除以温度 τ：等价于 τ=1，分布太平，正样本区分度低，效果差。
3) 只算单向损失：CLIP 必须对称，否则图像和文本空间不对齐。
4) 标签搞错：对角线是正样本，标签是 arange(N)，不是全 0 或全 1。
5) 温度设为固定小值：容易梯度爆炸或训练崩溃，应可学习并 clamp。
6) 混淆 InfoNCE 与 Triplet Loss：InfoNCE 是 softmax 形式，利用所有负样本；Triplet 只用一个正一个负，是不同范式。
7) 认为 batch 内负样本一定够：小 batch 时负样本少，效果受限，需用队列或跨卡聚合。

## 18. 语音转文字花费很高怎么解决

> **高频程度**：★★☆☆☆　|　**原题 ID**：`q1819`　|　**标签**：`概念基础` `juejin`

**考察点**：【由分类/标签推断】多模态 方向，重点考察 概念基础、juejin 的理解与工程落地、边界场景的掌握。

**回答框架**：语音转文字成本高的核心解法是：按场景分层选型（流式/离线、大模型/小模型、自建/…

**参考回答**
语音转文字成本高的核心解法是：按场景分层选型（流式/离线、大模型/小模型、自建/云服务），用VAD+分段+缓存+批处理把无效音频和重复计算砍掉，再对长音频做蒸馏/量化/端侧推理，而不是一味换更贵的ASR。

先把“贵”拆开看：ASR成本≈音频时长×单价，单价又由模型大小、是否流式、是否带标点/说话人分离/热词等决定。所以降本有两条主线：减少要识别的音频时长，降低单位时长成本。

1) 减少无效音频：用VAD（语音活动检测）先切掉静音、噪声、音乐段，只把有人声的片段送ASR。会议录音里静音常占30%-60%，这一步就能省一大半。再配合端点检测做分段，避免整段长音频反复解码。

2) 按场景选模型：实时字幕/语音助手用流式小模型（如流式Conformer、Paraformer-streaming）；离线转写用非流式大模型，精度高但可批处理。不要用大模型做实时，也不要用小模型硬扛高精度场景。

3) 缓存与去重：同一音频重复请求（用户重试、多端同步）做内容哈希缓存；热词、标点、ITN等后处理结果也缓存。

4) 批处理与并发：离线任务攒批，用GPU批推理提高吞吐，摊薄单条成本；云服务选按量+预留/竞价实例。

5) 模型压缩与端侧：对自建模型做量化（INT8/INT4）、蒸馏（大模型教小模型）、剪枝；简单命令词、短语音直接端侧识别，不上云。

6) 混合路由：先用小模型/端侧跑，置信度低或关键片段再送大模型复核，类似“草稿+精修”。

7) 业务层：能不给全文就不给全文，只给摘要/关键词；长音频先做说话人分离和分段，只转写需要的说话人。

通俗类比：ASR像请翻译，按小时收费。省钱不是换更便宜的翻译，而是先把没人说话的录音剪掉、把重复内容合并、简单内容让实习生（小模型）做，难的部分再请专家（大模型）复核。

**加分点**

1) 知道VAD本身也有成本，但远低于ASR，且可用轻量CRNN/FSMN；2) 了解流式ASR的chunk设计会影响延迟和算力，chunk越小越贵；3) 自建时可用ONNX/TensorRT量化，INT8通常精度损失<1%，吞吐提升2-4倍；4) 云厂商ASR按秒计费，长音频可先压缩采样率到8k/16k，但要注意宽带语音降采样会掉精度；5) 可提Whisper蒸馏到小模型（如distil-whisper）或使用MoE只激活部分参数；6) 缓存要按音频指纹+模型版本+参数做key，避免脏缓存。

**雷区**

1) 只说“换便宜的服务商”，忽略音频时长和无效片段才是大头；2) 以为VAD免费，实际VAD也有算力，但相对ASR可忽略；3) 盲目降采样/压缩导致识别率暴跌，反而要重跑更贵；4) 忽略流式与非流式的成本差异，实时场景硬上大模型；5) 缓存不做版本隔离，模型升级后返回旧结果；6) 只算GPU单价，不算带宽、存储、重试和人工校对成本。

## 19. 现在市面很多大模型，对彼此的对比了解么，比如说生成音频的哪个最好之类的

> **高频程度**：★★☆☆☆　|　**原题 ID**：`q2160`　|　**标签**：`概念基础` `juejin`

**考察点**：【由分类/标签推断】多模态 方向，重点考察 概念基础、juejin 的理解与工程落地、边界场景的掌握。

**回答框架**：大模型按模态分工，没有全能冠军；音频生成要分语音合成、音乐生成、音效生成三类，各…

**参考回答**
大模型按模态分工，没有全能冠军；音频生成要分语音合成、音乐生成、音效生成三类，各自有代表模型，选型看语言、时长、可控性和商用授权。

市面上的大模型可以按‘输入输出模态’和‘任务类型’两个维度来理解。

1) 按模态分：
- 文本/多模态理解与生成：GPT、Claude、Gemini、Qwen、DeepSeek、Llama 等，主要处理文字、图片、代码。
- 图像生成：Midjourney、Stable Diffusion、DALL·E、Flux、即梦等。
- 视频生成：Sora、可灵、Veo、Runway、Pika 等。
- 音频生成：这是最容易被笼统说成‘生成音频’的一类，实际要拆成三个子任务：
  a. 语音合成 TTS（文字转人声）：ElevenLabs、OpenAI TTS、Azure TTS、Google WaveNet、MiniMax、CosyVoice、Fish Audio、ChatTTS 等。ElevenLabs 在多语言自然度、情感和克隆上口碑最好；中文场景 CosyVoice、MiniMax、火山/讯飞也很强。
  b. 音乐生成：Suno、Udio、Stable Audio、Google MusicLM/MusicFX。Suno 和 Udio 目前是‘一句话生成完整歌曲’的第一梯队，Suno 在旋律完整度和中文歌上更出圈，Udio 在音质和细节控制上常被专业用户偏好。
  c. 音效/环境声生成：AudioGen、AudioLDM、Stable Audio Open 等，适合做游戏音效、短视频背景声。

2) 为什么没有‘最好’：
- 评测维度不同：自然度、相似度、延迟、可控性、版权、成本、语言覆盖。
- 闭源模型迭代快，榜单月月变；开源模型可私有化部署，适合数据敏感场景。
- 商用授权差异大：Suno/Udio 免费版通常不能商用，ElevenLabs 按字符计费，开源模型要看权重协议。

3) 通俗类比：
把大模型想成‘专科医生’。GPT/Claude 是全科医生，能看大部分病；Suno 是音乐制作人；ElevenLabs 是配音演员；Sora 是导演。你不会问‘哪个医生最好’，而是问‘我要看什么病、预算多少、要不要上门’。

4) 选型建议：
- 做中文有声书/客服：CosyVoice、MiniMax、Azure TTS。
- 做多语言、情感克隆：ElevenLabs。
- 做完整歌曲：Suno 或 Udio，先试听再定。
- 做游戏音效：Stable Audio Open 或 AudioLDM，可本地部署。
- 企业落地还要看：是否支持流式、并发、SLA、数据是否出境、是否允许商用。

**加分点**

1) 能指出音频生成不是单一任务，TTS/音乐/音效的模型架构不同：TTS 常用自回归 + 声码器（如 VALL-E、CosyVoice 用 LLM 做 token 预测再 vocoder），音乐生成常用扩散或 Transformer 建模长序列。
2) 知道评测集：TTS 看 MOS、WER、说话人相似度；音乐看 FAD、CLAP score；不能只看主观‘好听’。
3) 提到开源可私有化：CosyVoice、Fish Speech、Stable Audio Open 可本地部署，适合合规要求高的公司。
4) 提到版权风险：Suno/Udio 曾被唱片公司起诉，商用要谨慎；训练数据来源也是雷。
5) 提到工程细节：TTS 流式首包延迟、并发成本、SSML 控制、多音字和韵律，这些比‘哪个模型好’更影响落地。

**雷区**

1) 直接说‘XX 最好’而不区分任务，比如把 Suno 当成 TTS 用，或把 ElevenLabs 当成音乐生成。
2) 忽略语言和场景：英文最好的模型中文不一定好，中文多音字、儿化音、方言是常见坑。
3) 忽略商用授权和版权，免费 API 直接上生产。
4) 只看榜单不看延迟和成本，实际业务里流式延迟和并发费用往往比音质更致命。
5) 把‘大模型’等同于‘LLM’，以为音频生成也是同一个模型顺带做的，实际上多数是专用模型或专用 pipeline。

## 20. 而对于需要处理图像、实现像素级别的操作的场景，Canvas 更适用

> **高频程度**：★★☆☆☆　|　**原题 ID**：`q2424`　|　**标签**：`概念基础` `juejin`

**考察点**：【由分类/标签推断】多模态 方向，重点考察 概念基础、juejin 的理解与工程落地、边界场景的掌握。

**回答框架**：Canvas 是像素级绘图 API，适合图像处理、滤镜、逐像素操作等需要直接读写…

**参考回答**
Canvas 是像素级绘图 API，适合图像处理、滤镜、逐像素操作等需要直接读写位图的场景；而 SVG 是矢量 DOM，适合图形交互与缩放，不适合大规模像素运算。

Canvas 提供一块位图画布，通过 2D 上下文（CanvasRenderingContext2D）暴露 getImageData/putImageData、drawImage、globalCompositeOperation 等 API，让开发者能直接拿到 RGBA 像素数组（Uint8ClampedArray）做逐像素计算，例如灰度、卷积、抠图、色彩矩阵、实时滤镜。原理上，Canvas 的绘制结果是一张位图，浏览器可把它交给 GPU 合成，甚至通过 WebGL/WebGPU 做并行像素处理，因此适合图像编辑、视频帧处理、游戏渲染、图表大数据量绘制。SVG 则是基于 XML 的矢量 DOM，每个图形是独立节点，缩放不失真、可被 CSS/JS 单独操作，但像素级操作需要转成 Canvas 或借助 foreignObject，且节点数量大时 DOM 开销高。通俗类比：Canvas 像一张画布，你拿画笔直接涂像素，画完就是一张照片；SVG 像用积木拼图，每块积木都是可单独移动、放大的矢量图形。选择依据：需要逐像素、滤镜、高性能大量绘制选 Canvas；需要无损缩放、可访问性、节点级交互选 SVG。

**加分点**

1) getImageData 返回的是 Uint8ClampedArray，越界会 clamp 到 0-255，且读取会触发 GPU→CPU 回读，频繁调用是性能瓶颈，可用 OffscreenCanvas + Worker 或 WebGL 纹理做并行处理。2) Canvas 2D 的 globalCompositeOperation 支持 blend mode，可实现类似 Photoshop 的混合。3) 高清屏要用 devicePixelRatio 缩放 canvas 尺寸，否则像素模糊。4) 大图处理可用 createImageBitmap 异步解码，避免主线程阻塞。5) 与 SVG 互操作：可用 drawImage 把 SVG 画到 Canvas 再取像素。

**雷区**

1) 误以为 Canvas 只能画图形不能做像素操作，忽略 getImageData/putImageData。2) 认为 SVG 也能轻松做像素级滤镜，实际上 SVG 滤镜是声明式且性能/能力有限。3) 忽略 Canvas 是立即模式、无 DOM 节点，无法像 SVG 那样单独绑定事件，需自己做命中检测。4) 忘记 Canvas 位图在高分屏下会模糊，未处理 DPR。5) 把 Canvas 和 WebGL 混为一谈，2D 上下文并不自动 GPU 加速所有像素操作。

## 21. 开放目标检测： 支持无限类的目标物体，即用户可自定义想要识别的目标、属性、行为，进行高效而准确地识别及定位，实现对多样化

> **高频程度**：★★☆☆☆　|　**原题 ID**：`q2908`　|　**标签**：`概念基础` `juejin`

**考察点**：【由分类/标签推断】多模态 方向，重点考察 概念基础、juejin 的理解与工程落地、边界场景的掌握。

**回答框架**：开放目标检测（Open-Vocabulary/Object Detection）…

**参考回答**
开放目标检测（Open-Vocabulary/Object Detection）指模型不局限于训练时固定的类别集合，而是能根据用户以文本（或图像示例）自定义的任意类别、属性、行为进行识别与定位，核心在于用视觉-语言对齐把'检测'从闭集分类变成开放语义匹配。

传统目标检测（如 YOLO、Faster R-CNN）是闭集检测：训练时类别数固定（如 COCO 80 类），输出层是固定维度的分类头，遇到新类别必须重新标注数据并重训。开放目标检测要解决的是'无限类'问题，即用户随时用自然语言描述想找什么（如'戴红帽子的行人''正在打电话的狗'），模型就能给出边界框和类别。

核心原理有三条路线：
1) 视觉-语言对齐：用 CLIP 这类图文对比学习模型，把图像区域和文本描述映射到同一嵌入空间，检测时用文本嵌入替代固定分类头，算区域特征与文本嵌入的相似度即可。代表：ViLD、GLIP、Grounding DINO、OWL-ViT。
2) 把检测转成'文本提示+定位'：如 Grounding DINO 用文本编码器与图像特征做跨模态注意力，输出与文本短语对应的框；GLIP 把检测建模成 phrase grounding，统一了检测和定位。
3) 生成式/大模型路线：如基于 LLM/VLM 的检测（如 GPT-4V 类、以及用 LLM 生成候选类别再交给开放检测器），或 DETR 类端到端结构配合开放词汇头。

通俗类比：闭集检测像'只认识菜单上固定菜品的服务员'；开放检测像'能听懂你任意描述的服务员'——你说'那个穿蓝衣服、在跑的人'，它也能指出来。

适用场景：需要频繁新增类别的工业质检、零售货架、自动驾驶长尾物体、机器人指令跟随、内容审核、遥感等。

关键挑战：开放词汇下的误检/漏检、文本歧义、属性与行为（动作）识别比静态类别更难、推理效率（文本编码与跨模态计算开销）、以及如何用少量标注高效适配新场景（如 prompt tuning、LoRA 微调）。

**加分点**

1) 能区分 Open-Vocabulary（类别开放）与 Open-Set（拒绝未知类）与 Zero-Shot（零样本）三个概念：开放词汇强调用语言描述任意类，零样本是其中一种评测设定，开放集强调'未知即拒识'。2) 知道 GLIP 把检测统一为 phrase grounding，用 grounding 数据（如 GoldG）预训练可显著提升开放词汇能力；Grounding DINO 用'图像-文本跨模态融合+对比去噪'实现强 zero-shot。3) 了解评测：LVIS（1200+ 类长尾）、OV-COCO、ODinW 等，常用 AP_r（rare 类）衡量开放能力。4) 工程踩坑：文本 prompt 模板（如 'a photo of a {class}'）对 CLIP 类模型影响大；类别同义词/层级需做 prompt ensemble；开放检测器在密集小目标上召回差，常需与闭集检测器融合。5) 效率：可缓存文本嵌入，避免每帧重复编码；用蒸馏把开放能力压到小模型。

**雷区**

1) 把开放目标检测等同于'零样本检测'或'开放集检测'，概念混用。2) 以为只要换个分类头就能无限类，忽略视觉-语言对齐和跨模态训练数据的重要性。3) 认为开放检测可以完全替代闭集检测：实际在固定类别、追求高精度和低延迟场景，闭集专用模型仍更优。4) 忽略'属性/行为'与'类别'的差异：行为识别通常需要时序或更细粒度建模，不是简单文本匹配能解决。5) 只谈模型不谈数据与评测，忽略 grounding 数据、prompt 工程和长尾评测的重要性。

## 22. OCR 抽取效果不好，需要怎么排查问题

**参考回答**
OCR 抽取效果差要按“图像质量→检测框→识别→后处理/结构化→业务评测”分层定位，用可视化+分模块指标先定位瓶颈再针对性优化。

排查思路（假设我做过一个票据/证件 OCR 抽取项目）：

1. 先明确“效果不好”的定义。是整行漏检、字符错、字段错位，还是结构化字段（如金额、日期）抽取错？要建立分层评测集：检测指标（召回/精确、IoU）、识别指标（CER/WER）、字段级指标（字段准确率、F1）。没有分模块指标就只能瞎调。

2. 图像层排查。检查分辨率、模糊、倾斜、透视、光照、反光、印章遮挡、压缩噪声。做法：抽样可视化原图+预处理图；统计 DPI、清晰度（Laplacian 方差）、倾斜角分布。若图像差，先做去噪、二值化、透视矫正、超分，或引导用户重拍。

3. 检测层排查。把检测框画回原图，看漏检/误检/框不准。常见原因：小目标、长文本、密集文本、非水平文本、训练域与线上域不一致。对策：换 DBNet/PANet 等检测器，加数据增强（旋转、透视、模糊），调 anchor/阈值，或对特定版式做模板/版面分析。

4. 识别层排查。裁剪检测框单独送识别，看是检测错还是识别错。常见原因：字体/语种不匹配、字符集缺失、竖排/弯曲文本、低分辨率、训练数据与真实分布偏差。对策：补充真实场景标注、换 CRNN/SVTR/TrOCR 等模型、加语言模型/词典约束、对关键字段做正则校验。

**加分点**

1. 能说出用 CER/WER、字段级 F1、检测 IoU 阈值（如 0.5）分模块量化，而不是只看最终准确率。
2. 知道训练/推理预处理一致性坑：训练时 resize 方式、归一化、颜色空间与线上不一致会显著掉点。
3. 能提置信度校准与兜底：低置信度走人工/LLM 复核，避免错误直接进业务。
4. 有数据闭环意识：badcase 自动回流、按版式/来源分桶评测，防止整体指标掩盖长尾。
5. 了解主流方案演进：检测 DBNet/PANet，识别 CRNN/SVTR/TrOCR，端到端 Donut 等，能按场景选型。

**雷区**

1. 一上来就换模型/调参，没有分层指标和可视化，无法定位是检测、识别还是后处理问题。
2. 把 OCR 和结构化抽取混为一谈，字段错就怪 OCR，实际是规则/模板/LLM 抽取问题。
3. 忽略图像预处理与训练分布不一致，或线上图片质量差却只优化模型。
4. 只用整体准确率评估，不看分版式/分字段指标，长尾问题被平均掩盖。
5. 不做置信度兜底，低质量结果直接进业务导致资损。

## 23. 你的一条语音大概有多大（几十k到几百k）

> **高频程度**：★★☆☆☆　|　**原题 ID**：`q3335`　|　**标签**：`概念基础` `juejin`

**回答框架**：一条语音的大小取决于采样率、位深、声道数和时长，常见 16kHz/16bit/单…

**参考回答**
一条语音的大小取决于采样率、位深、声道数和时长，常见 16kHz/16bit/单声道下约 32KB/秒，所以几秒到几十秒的语音通常在几十 KB 到几百 KB。

语音文件大小 = 采样率 × 位深 × 声道数 × 时长 ÷ 8（字节）。以最常见的语音场景为例：采样率 16kHz、位深 16bit、单声道，则每秒数据量为 16000 × 16 × 1 ÷ 8 = 32000 字节，即约 32KB/s。因此：1 秒约 32KB，5 秒约 160KB，10 秒约 320KB，30 秒约 960KB。如果使用 8kHz 电话采样率，则每秒约 16KB，5 秒约 80KB。如果采用压缩编码，如 Opus、AAC、MP3，大小会显著降低：Opus 在 16kbps 下每秒仅约 2KB，5 秒约 10KB；AAC 在 64kbps 下每秒约 8KB，5 秒约 40KB。所以面试中回答“几十 KB 到几百 KB”是合理的，但需要说明前提：未压缩 PCM 且时长几秒到十几秒。通俗类比：采样率像每秒拍多少张照片，位深像每张照片用多少种颜色，声道数像用几只麦克风同时录，时长就是录了多久；文件大小就是这些因素相乘。

**加分点**

1. 能区分“原始 PCM”和“压缩编码”：PCM 是裸数据，WAV 通常只是加文件头；Opus/AAC/MP3 是有损压缩，适合网络传输。2. 知道奈奎斯特采样定理：语音主要能量在 300Hz~3.4kHz，所以电话用 8kHz 采样；宽带语音用 16kHz；音乐才需要 44.1kHz/48kHz。3. 能结合工程场景：ASR 通常要求 16kHz 单声道 PCM，因为模型训练多基于此；实时语音通话常用 Opus 16~24kbps，兼顾延迟和音质。4. 能算带宽：16kHz/16bit/单声道 PCM 约 256kbps，100 路并发就是 25.6Mbps，所以服务端通常要转码或压缩。5. 知道文件头开销：WAV 头约 44 字节，短语音时不可忽略；但几十 KB 级别通常可忽略。

**雷区**

1. 只背“几十 KB 到几百 KB”而不说前提，面试官会追问采样率、位深、时长、是否压缩。2. 把采样率和位深混淆，误以为 16kHz 就是 16bit。3. 忽略声道数，误把立体声当单声道，大小会翻倍。4. 认为 MP3 和 WAV 一样大，或认为压缩后大小与时长严格线性但忽略码率波动。5. 忘记除以 8：位是 bit，字节是 Byte，1 Byte = 8 bit，这是最常见的计算错误。6. 把“语音”和“音乐”混为一谈，音乐常用 44.1kHz/16bit/立体声，每秒约 176KB，远大于语音。

直播/视频理解是把时序多模态信号转成结构化语义，VLM 是用视觉编码器+LLM 做跨模态对齐与生成，直播场景核心难点在实时性、长时序和弱标注。

三、通俗类比。视频理解像看一部电影后写影评；VLM 像给一个博学的盲人配了一双眼睛，眼睛负责看，大脑（LLM）负责说；直播理解像一边看球赛一边实时解说，不能等比赛结束再总结。

五、工程链路。抽帧（1fps 或场景切换）→ 视觉编码 → 时序聚合 → 与 ASR/弹幕文本融合 → LLM 生成结构化 JSON（类别/片段起止/描述）→ 下游审核或推荐。

## 25. tts模型音频是怎么处理的，怎么离散成token的

> **高频程度**：★★☆☆☆　|　**原题 ID**：`q3482`　|　**标签**：`工程落地` `nowcoder`

**考察点**：【由分类/标签推断】多模态 方向，重点考察 工程落地、nowcoder 的理解与工程落地、边界场景的掌握。

**回答框架**：TTS模型通常用神经音频编解码器（如SoundStream/EnCodec）把连…

**参考回答**
TTS模型通常用神经音频编解码器（如SoundStream/EnCodec）把连续音频压缩成离散token，或直接用梅尔谱+声码器两阶段，离散化靠RVQ（残差向量量化）实现。

在TTS工程中，音频处理与离散化主要有两条路线：

1) 两阶段（传统/主流）：文本→声学模型→梅尔频谱（连续帧，如80维、帧移10ms）→声码器（HiFi-GAN、WaveNet）→波形。这里音频不直接离散成token，而是用连续梅尔谱作为中间表示。优点是声码器可独立优化，音质好；缺点是梅尔谱有信息损失，且两阶段误差累积。

2) 端到端离散token路线（近年主流，如VALL-E、Tortoise、Bark）：先用神经音频编解码器把波形编码成离散token，再让TTS模型自回归/非自回归预测token，最后用解码器还原波形。

离散化核心是神经音频编解码器，典型结构：编码器（卷积下采样，如从24kHz降到50Hz帧率）→量化器→解码器。量化器常用RVQ（Residual Vector Quantization）：
- 第一层量化器把编码器输出向量量化到码本中最近邻，得到token1；
- 计算残差（原向量-量化向量），第二层再量化残差，得到token2；
- 重复N层（如8层），每层码本大小通常1024。
这样每帧音频得到N个token（如8个），帧率约50Hz，即每秒400个token。

工程上关键点：
- 码本大小与层数权衡：码本越大、层数越多，重建质量越高，但token序列越长，TTS模型建模难度和推理成本越高。
- 训练目标：重构损失（L1/L2）+ 量化损失（码本承诺损失）+ 对抗损失（GAN判别器）+ 特征匹配损失，常用SoundStream/EnCodec方案。
- 离散token的TTS建模：VALL-E用两阶段：先预测第一层码本（粗粒度），再以第一层为条件预测其余层（细粒度），类似分层自回归。
- 推理时：TTS模型输出token序列，送入解码器（如EnCodec decoder）还原波形，可流式。

例子：EnCodec在24kHz音频上，帧率75Hz，8层RVQ，每层1024码本，每秒600个token。VALL-E用类似配置，但帧率50Hz。

踩坑：
- 梅尔谱离散化（如k-means）效果差，因为梅尔谱本身连续且高维，直接聚类会丢失细节。
- RVQ层数太多导致token序列过长，自回归TTS推理慢且易错。
- 码本坍塌：部分码本向量很少被使用，需用EMA更新或重启策略。
- 训练解码器时，若直接用TTS预测的token（而非真实token）做输入，会有暴露偏差，需 scheduled sampling 或 teacher forcing 调整。

**加分点**

1) 源码级：EnCodec的RVQ实现中，每层量化后残差传递，码本用EMA更新，且量化损失用commitment loss（β=0.25）。2) 论文：SoundStream提出RVQ+对抗训练，EnCodec改进为多尺度STFT判别器。3) 工程权衡：VALL-E用两阶段预测，第一层码本预测用自回归，其余层用非自回归，平衡质量与速度。4) 踩坑：RVQ层数增加时，后层码本利用率下降，需用码本重置或随机采样。5) 流式：解码器需支持因果卷积，否则无法流式合成。

在音视频算法优化中，Bad Case 通常指模型预测与真实标签差异较大的样本。处理流程如下：
1. 收集与标注：建立 Bad Case 收集管道，从线上日志、用户反馈、测试集中挖掘，并人工复核确保标签正确。

3. 针对性优化：
   - 数据：补充类似样本、数据增强、重标注、难例挖掘。
   - 模型：调整损失函数（如 Focal Loss 聚焦难例）、集成、蒸馏、引入外部知识。
   - 工程：修复预处理/后处理不一致，增加规则兜底。
4. 验证与监控：在保留集上评估，确保整体指标不降；A/B 测试验证线上效果；建立持续监控，防止回归。
关键权衡：不要为了个别 Bad Case 牺牲整体性能，需评估修复成本与收益。

**加分点**

1. 引用论文方法：如 Focal Loss 解决难例不平衡，或 OHEM 在线难例挖掘。
2. 工程踩坑：曾遇到因训练/推理预处理不一致（如音频重采样算法不同）导致大量 Bad Case，通过统一预处理库解决。
3. 数据闭环：设计自动化管道，将线上 Bad Case 自动回流至训练集，并定期重训。
4. 可解释性：使用 SHAP、注意力可视化分析模型决策，定位特征问题。
5. 成本权衡：对于长尾 Bad Case，采用规则兜底而非模型优化，保证 ROI。

**雷区**

1. 盲目过拟合 Bad Case：直接针对个别样本调参，导致模型泛化下降。
2. 忽视数据质量：未检查标注错误，在错误标签上优化。
3. 忽略线上一致性：训练和推理环境差异导致 Bad Case，却只改模型。
4. 缺乏整体评估：只关注 Bad Case 修复，未监控整体指标变化。
5. 单点优化：未从系统角度分析，如特征管道、后处理逻辑等。

## 27. Q17：Stable Diffusion 中的潜在扩散模型（LDM）原理是什么

> **高频程度**：★★☆☆☆　|　**原题 ID**：`q3732`　|　**标签**：`概念基础` `zhihu`

**考察点**：【由分类/标签推断】多模态 方向，重点考察 概念基础、zhihu 的理解与工程落地、边界场景的掌握。

**回答框架**：LDM 的核心是先用 VAE 把图像压缩到低维潜在空间，再在潜在空间上做扩散/去…

**参考回答**
LDM 的核心是先用 VAE 把图像压缩到低维潜在空间，再在潜在空间上做扩散/去噪，最后解码回像素空间，从而在几乎不损失生成质量的前提下把计算量降低一到两个数量级。

传统扩散模型（DDPM）直接在像素空间操作：一张 512×512×3 的图有约 78 万个维度，每一步去噪都要让 U-Net 在这个高维空间上跑一遍，训练和采样都极慢。LDM（Rombach 等，CVPR 2022）的思路是“先压缩、再扩散”：

1) 感知压缩阶段：训练一个 VAE（编码器 E + 解码器 D），把图像 x 编码成潜在表示 z = E(x)，维度比如 64×64×4，即下采样 8 倍、通道压到 4，空间维度缩小 64 倍。VAE 用重建损失 + KL 正则 + 感知损失/对抗损失训练，保证解码回来的图在感知上几乎无损。

2) 潜在扩散阶段：在 z 上训练扩散模型（通常是 U-Net）。前向过程按同样公式加噪 z_t = sqrt(ᾱ_t)·z_0 + sqrt(1-ᾱ_t)·ε，反向过程学习预测噪声 ε_θ(z_t, t, c)，条件 c 可以是文本（通过 CLIP/T5 编码后做 cross-attention）、类别、掩码等。因为 z 的维度远小于 x，U-Net 的算力主要花在低维空间，训练和采样都快得多。

3) 采样与解码：从纯高斯噪声 z_T 出发，用 DDIM/PLMS/DPM-Solver 等采样器迭代去噪得到 z_0，再经解码器 x̂ = D(z_0) 还原成图像。

通俗类比：像素空间扩散像“直接在 4K 原片上逐帧修图”，又慢又费显存；LDM 像“先把片子压成小样（缩略图）在缩略图上修，修完再放大回原片”。因为图像的大部分信息是冗余的，真正的语义结构在低维流形上就能表达，所以在潜在空间去噪等价于在语义层面去噪。

适用场景：高分辨率文生图（Stable Diffusion 系列）、图像编辑/Inpainting、超分、视频生成（如 SVD、部分视频扩散模型也沿用该范式）。关键超参是下采样因子 f（SD 用 f=8）和潜在通道数（SD 用 4），f 越大越快但重建细节损失越大，需要权衡。

**加分点**

1) 论文里明确区分“感知压缩”和“语义压缩”：LDM 只做适度感知压缩（f=4~16），把语义压缩交给扩散模型本身，避免像 VQGAN 那样压缩过狠导致信息丢失。2) 工程细节：SD 的 VAE 有 scaling factor（约 0.18215），训练扩散前要把 z 乘上它把方差归一化，否则噪声调度不匹配。3) 采样器选择：DDIM 可 20~50 步，DPM-Solver++ 可 10~20 步，本质是在 ODE/SDE 求解上做高阶近似。4) 条件注入：文本经 cross-attention 注入 U-Net，这是 classifier-free guidance 能生效的基础；CFG 通过 ε = ε_uncond + s·(ε_cond - ε_uncond) 控制文本贴合度。5) 后续演进：SDXL 用双文本编码器、SD3/Flux 转向 DiT + 流匹配（rectified flow），但“潜在空间扩散”这一范式没变。

**雷区**

1) 误以为 LDM 是在像素空间扩散、只是网络更小；2) 以为 VAE 只是普通自编码器，忽略其感知/对抗损失对重建质量的关键作用；3) 把“潜在空间”和“文本嵌入空间”混为一谈，实际上文本条件是通过 cross-attention 注入，不是把文本编码当潜在变量；4) 认为下采样越大越好，忽略 f 过大导致细节丢失、文字/小物体崩坏；5) 混淆 LDM 与 Latent Diffusion 的“latent”与 GAN 的 latent code，二者含义不同；6) 忽略 scaling factor 和噪声调度在潜在空间与像素空间不一致的坑。

## 28. 对比学习：SimCSE / CLIP，拉近正样本、推远负样本

> **高频程度**：★★☆☆☆　|　**原题 ID**：`q3803`　|　**标签**：`概念基础` `zhihu`

**考察点**：【由分类/标签推断】多模态 方向，重点考察 概念基础、zhihu 的理解与工程落地、边界场景的掌握。

**回答框架**：对比学习的核心是把语义相近的样本在向量空间拉近、把不相关的推远；SimCSE 用…

**参考回答**
对比学习的核心是把语义相近的样本在向量空间拉近、把不相关的推远；SimCSE 用 dropout 造正样本做文本句向量，CLIP 用图文配对做跨模态对齐，二者都是 InfoNCE 损失的特例。

对比学习（Contrastive Learning）本质是一种表示学习范式：不直接学分类标签，而是学一个嵌入空间，让'正样本对'距离小、'负样本对'距离大。类比：把每个样本想象成地图上的城市，正样本是同一座城市的不同照片（不同角度/天气），负样本是别的城市；训练目标是让同城照片聚成一团，不同城市彼此远离。

关键组件有三：1) 正负样本构造；2) 相似度度量（通常余弦相似度）；3) 损失函数（最常用 InfoNCE / NT-Xent）。InfoNCE 形式为 L = -log[ exp(sim(z_i,z_i+)/τ) / Σ_j exp(sim(z_i,z_j)/τ) ]，其中 τ 是温度系数，控制分布的尖锐程度。它可看作在 N 个候选中做 softmax 分类，也可从互信息下界角度理解（最大化正对互信息的下界）。

SimCSE（Simple Contrastive Sentence Embedding）：
- 无监督版：把同一句话喂给 BERT 两次，由于 dropout 随机性得到两个略有差异的 embedding，互为正样本；同一个 batch 内其他句子作为负样本。非常巧妙——不需要任何标注，仅靠 dropout 就构造出正对。
- 有监督版：用 NLI 数据集，entailment 句对为正，contradiction 为硬负样本。
- 训练目标就是 batch 内的 InfoNCE，负样本即 in-batch negatives。
- 效果：在 STS 语义相似度任务上大幅超过普通 BERT/SimBERT，且实现极简。

CLIP（Contrastive Language-Image Pre-training）：
- 正样本是配对的（图像, 文本），负样本是 batch 内其他所有不配对的图文组合。
- 双塔结构：图像编码器（ViT/ResNet）+ 文本编码器（Transformer），各自映射到同一维度空间，做 L2 归一化后算余弦相似度。
- 损失是对称的 InfoNCE：图像→文本 和 文本→图像 两个方向各算一次再平均。
- 用 4 亿图文对训练，得到可迁移的零样本分类器：把类别名写成 prompt（如 'a photo of a dog'），与图像算相似度取最大即可分类。

对比总结：SimCSE 是单模态、靠 dropout/NLI 造正对，解决句向量各向异性问题；CLIP 是跨模态、靠天然图文配对造正对，解决图文对齐与零样本迁移。两者共享同一套对比学习骨架，区别只在正负样本来源和编码器结构。

**加分点**

1) 温度 τ 的作用：SimCSE 论文发现 τ 对无监督版影响很大，小 τ 会让难负样本权重更大，论文推荐 0.05；CLIP 则把 τ 设为可学习参数（初始 0.07），等价于 logits 缩放。2) 负样本数量：InfoNCE 中负样本越多，互信息下界越紧，所以 CLIP 用超大 batch（32768）并配合梯度缓存/AllGather 跨卡交换特征。3) SimCSE 的 dropout 正对本质是'数据增强'，论文还对比了删除、替换、裁剪等增强，发现 dropout 最好，且发现无监督 SimCSE 能缓解 BERT 表示的各向异性（uniformity 更好）。4) 硬负样本：有监督 SimCSE 用 contradiction 做硬负样本显著提升；CLIP 中 batch 内相似但不配对的样本也是天然硬负。5) 对齐与均匀性（alignment & uniformity）是衡量对比表示质量的两个指标，可用来解释为什么 SimCSE 有效。

**雷区**

1) 误以为 SimCSE 需要标注数据——无监督版完全不需要，只靠 dropout。2) 把 CLIP 的负样本理解成'随机采样'——其实是同 batch 内所有非配对组合，是 in-batch negatives，且对称计算。3) 忽略温度系数 τ，或以为它只是超参不重要。4) 混淆对比学习与度量学习/三元组损失：三元组是显式选正负，InfoNCE 是 batch 内 softmax，负样本数量级不同。5) 以为 CLIP 只能做分类——它本质是图文对齐模型，可用于检索、生成引导（如 DALL·E）、零样本分类等。6) 认为 SimCSE 的 dropout 正对是'两次不同模型'——其实是同一模型不同 dropout mask。

## 29. Q16：VLM（视觉语言模型）的主流架构设计模式有哪些？LLaVA 和 Qwen-VL 的架构有何异同？

> **高频程度**：★★☆☆☆　|　**原题 ID**：`q3832`　|　**标签**：`架构设计` `zhihu`

**考察点**：【由分类/标签推断】多模态 方向，重点考察 架构设计、zhihu 的理解与工程落地、边界场景的掌握。

**回答框架**：VLM 主流是“视觉编码器 + 投影/对齐模块 + LLM 解码器”三段式，LL…

**参考回答**
VLM 主流是“视觉编码器 + 投影/对齐模块 + LLM 解码器”三段式，LLaVA 用简单 MLP 投影把 CLIP 特征映射到 LLM 词嵌入空间，Qwen-VL 用可学习 Query 的 Cross-Attention 重采样器并支持多图/定位，二者核心差异在视觉-语言对齐模块的复杂度与位置编码/分辨率策略。

一、主流架构设计模式
1) 三段式（最主流）：视觉编码器（ViT/CLIP/SigLIP）→ 视觉-语言连接器（Projector/Resampler/Adapter）→ LLM 解码器。数据流：图像切 patch → ViT 出 N 个视觉 token → 连接器压缩/映射为 K 个 LLM 可读 token → 与文本 token 拼接 → 自回归生成。
2) 按连接器划分：
   - 线性/MLP 投影（LLaVA、MiniGPT-4）：实现简单、训练便宜，视觉 token 数=patch 数，长图/高分辨率时序列爆炸。
   - Query-based 重采样（Qwen-VL、Flamingo、BLIP-2）：用固定数量可学习 query 做 cross-attention，把任意多视觉 token 压成固定 K 个，控制上下文长度、易扩展多图/视频。
   - 交叉注意力注入（Flamingo、Idefics）：在 LLM 层间插 gated cross-attention，保留 LLM 文本能力，但改动大、训练/推理成本高。
   - 早期融合/统一 token（Chameleon、Fuyu）：视觉直接当 token 进 Transformer，无独立编码器，扩展性好但对齐难、算力大。
3) 训练范式：通常三阶段——对齐预训练（冻结 LLM，只训连接器）→ 多任务指令微调（解冻 LLM/编码器）→ 偏好对齐（DPO/RLHF）。

二、LLaVA vs Qwen-VL 异同
相同点：都是“ViT + 连接器 + 自回归 LLM”三段式；都用 CLIP 系视觉编码器；都做两阶段以上训练；都靠指令数据提升对话/OCR/推理能力。
不同点：
- 连接器：LLaVA-1.5 用两层 MLP 直接投影，视觉 token 与 patch 一一对应；Qwen-VL 用单层 cross-attention 的 Resampler，把变长视觉特征压成固定 256 个 query token。
- 分辨率/位置：LLaVA 固定 336/336²，靠 AnyRes 切图提升分辨率；Qwen-VL 支持动态分辨率，位置编码用 2D-RoPE 并做绝对位置编码，利于定位。
- 能力：Qwen-VL 原生支持 grounding（输出 bbox）、多图、OCR、中文，训练数据含检测/定位任务；LLaVA 偏通用对话与英文 VQA。
- 词表/LLM：LLaVA 基于 Vicuna/Llama，Qwen-VL 基于 Qwen，中文与长上下文更强。
文字示意：
LLaVA: Image→ViT→(N patch tokens)→MLP→N tokens→[concat text]→LLM→text
Qwen-VL: Image→ViT→(N patch tokens)→Resampler(cross-attn, 256 query)→256 tokens→[concat text]→LLM→text/bbox

三、取舍与扩展性
MLP 投影：简单、保真度高，但 token 多、长上下文贵；Resampler：压缩率高、多图/视频友好，但可能丢细粒度信息，需更多对齐训练。选型看任务：细粒度 OCR/定位偏保留高分辨率 token，长视频/多图偏 query 压缩。

**加分点**
