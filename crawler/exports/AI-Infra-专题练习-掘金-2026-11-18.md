## 训练与参数高效微调

原文发布于 2026-10-18，以下各题依照原文 Q1 至 Q14 对应。[掘金题单](https://juejin.cn/post/7697626465429520411)

### Q1 · 什么时候值得微调模型？

当目标是稳定改变输出格式、行为或任务能力，且有代表性的训练和验证样本时，可评估微调。先与提示词或检索基线比较，防止训练只记住样例。

### Q2 · 全参数微调和 PEFT 的资源差异在哪里？

全参训练为大多数权重维护梯度与优化器状态。PEFT 冻结基座，仅更新较少参数，显著缩小可训练状态；激活和基座前向仍需预算。

### Q3 · 微调与 RAG 如何取舍？

频繁变化或需要引用的知识可从检索注入，稳定的输出行为和任务适配可通过微调学习。分别评估检索召回与生成表现，再决定是否叠加。

### Q4 · LoRA 怎样近似权重更新？

冻结原始矩阵，用两个低秩矩阵的乘积表示更新项。训练参数规模随秩增长，可在支持的部署路径上合并权重或动态加载适配器。

### Q5 · LoRA 的秩和缩放如何选择？

秩控制更新子空间容量与参数量，缩放影响更新幅度。按固定的数据切分比较少量候选，同时记录目标层、学习率和采用的缩放公式。

### Q6 · QLoRA 和常规 LoRA 有何区别？

QLoRA 将冻结的基座以低比特格式存储，在计算时采用相应的反量化或高精度计算路径，适配器接收梯度。收益主要来自减小基座的内存占用。

### Q7 · RLHF 训练的反馈从哪里来？

从同一提示下多个回答的偏好比较构建反馈，经典流程先拟合奖励模型，再在约束下优化策略。要监测奖励过度优化和通用能力回退。

### Q8 · DPO 怎样使用偏好对？

同一提示提供偏好与非偏好回答，损失直接比较策略相对参考模型的两种回答的对数概率差。关键是偏好数据质量、参考策略和正则强度。

### Q9 · 偏好数据怎样控制标注成本和噪声？

先写可执行的偏好规范，在小批样本上做交叉标注和分歧分析，再优先标注差异大或覆盖薄弱的场景，保留独立评测集。

### Q10 · 训练 OOM 怎么定位？

记录前向、反向和优化器更新的峰值。激活占用高可减小 microbatch 或重计算，状态占用高可用分片或 PEFT，同时核查序列长度和碎片。

### Q11 · 如何发现并减轻灾难性遗忘？

保留基座能力回归集，与目标任务一起评估。可减小学习率、缩短训练或混入合适的通用数据，并比较适配器与全参训练的退化曲线。

### Q12 · LoRA、QLoRA、Adapter 和 Prefix-Tuning 如何选择？

分别比较可训练参数位置、基座驻留精度、序列额外开销和推理部署路径。用业务任务效果、训练峰值显存和服务成本共同决策。

### Q13 · 微调数据怎么做质量控制？

统一格式和对话模板，检查来源、去重及训练评测泄漏，抽查指令与答案是否一致。按难度和场景分层切分，记录清洗版本。

### Q14 · 后训练工具链怎样与集群条件匹配？

先画出数据、前反向、采样和评估的资源需求。选择能支持所需分片、并行与 checkpoint 的组合，先跑单节点正确性，再测多节点扩展和断点恢复。

## 推理框架

原文发布于 2026-10-20，以下各题依照原文 Q1 至 Q27 对应。[掘金题单](https://juejin.cn/post/7698269589705670719)

### Q1 · 怎样给 vLLM、SGLang 和 TensorRT-LLM 做第一轮选型？

先排除无法运行目标模型、精度或硬件的组合，再比较请求结构。重复前缀较多时测缓存命中后的收益，固定 NVIDIA 部署可测试专用内核。最后比较达到同一延迟目标时的有效吞吐。

### Q2 · KV cache 为什么适合分页管理？

把逻辑连续的 token 映射到可分散分配的物理块，请求增长时再取块，避免为每个请求预留最大长度。代价有尾块浪费、块表和寻址开销。

### Q3 · RadixAttention 与分页管理分别解决哪一层问题？

前缀树把相同 token 序列对应的 KV 找出来供多个请求复用，分页管理解决物理块的分配与回收。两种机制可以配合。

### Q4 · 如何比较三种引擎的显存管理？

固定可用显存、模型、KV 数据类型和并发，观察权重、活动 KV、缓存块、图或工作区各自占用。加入长短请求混合的稳态和高峰，检查驱逐、重算和 OOM。

### Q5 · 连续批处理如何安排新旧请求？

在迭代边界移出完成的请求，加入等候请求，按 token 预算安排 prefill 和 decode。观察短请求是否被长提示阻塞以及吞吐是否达到目标。

### Q6 · 如何比较引擎的结构化输出？

用同一套 JSON Schema 或语法测试约束覆盖、合法率、首次编译耗时和每步解码开销。特别检查流式增量、转义、工具调用和不支持的约束。

### Q7 · 怎样读一份推理引擎跑分？

先对齐硬件、精度、模型、生成长度和到达过程。离线的总 tokens/s 与在线符合延迟约束的完成量回答不同问题，不能直接按表中峰值排序。

### Q8 · 如何核对推理框架的量化能力？

沿模型格式、目标 GPU、可用内核逐项核对。权重量化与 KV 量化分开验证，记录精度损失、峰值显存、不同 batch 下的速度。

### Q9 · 在线聊天与离线批处理的选型条件有何区别？

在线场景优先看尾部首 token 时延及输出间隔，离线场景比较完成同一数据集的时间和成本。两者都要验证代表性长度分布和输出质量。

### Q10 · 生产中遇到 OOM、时延抖动或吞吐低，先看什么？

先区别加载时 OOM 和运行时 KV 增长，拆开排队、prefill 和 decode。对齐输入分布，观察每卡显存、等待队列和执行时间，再逐项调整 token 预算或并行度。

### Q11 · 分页为何有机会提高服务吞吐？

碎片和预留降低后，更多有效序列可以同时驻留，批次也更容易填满。若服务已受算力、带宽或低流量限制，节约显存未必提高完成量。

### Q12 · 哪些负载最能体现前缀缓存价值？

相同长系统提示、多分支生成和共享上下文带来的收益较大。要计算命中的 token 数而非只看请求命中率，并把热缓存和冷启动分别测量。

### Q13 · TensorRT-LLM 优化收益及工程成本来自哪里？

算子融合、针对硬件的内核与运行时调度都可能带来收益。需要检查目标 GPU、模型变体、量化和动态形状的实际可用路径，并为版本迁移预留验证成本。

### Q14 · 投机解码何时可能变慢？

草稿模型提出多个 token，目标模型批量验证。接受长度小、草稿生成慢或本来已充分批处理时，新增开销可能抵消收益。用相同采样配置比较端到端表现。

### Q15 · 两个推理引擎能怎样共存？

可以作为独立服务分别承载流量，通过路由比较成本或支持不同模型。若要在请求中途切换，必须处理 tokenizer、KV 布局、位置和采样状态的兼容性。

### Q16 · 为什么拆开 prefill 与 decode 部署？

两阶段的计算形态和延迟目标不同，分池可独立扩容、减少互相干扰。跨池复制 KV、排队和额外网络资源决定拆分是否值得。

### Q17 · DeepSeek 系列模型部署时要重点测什么？

以实际模型配置核对注意力、KV 表示和专家路由。记录 KV 容量、专家负载不均衡、跨卡通信和热点，分开观察长输入与大并发。

### Q18 · SGLang 和 LMDeploy 如何评估新功能对业务的意义？

固定发行版与硬件，逐项验收模型支持、缓存、量化、工具调用等实际需求。先做正确性回归，再拿生产流量分布做对照。

### Q19 · 如何核验指定日期前三个推理框架的版本变化？

从三个项目的 release/tag 取得当日以前最后一个稳定版本，逐项记录默认后端、弃用参数、模型格式和升级步骤。保留锁定镜像与回滚样例。

### Q20 · 怎样设计一场可以复跑的横评？

保存镜像摘要、启动参数、模型修订号、数据集与随机种子。固定请求到达轨迹，分别测冷启动与热运行，报告成功率、P50/P99 和符合 SLO 的吞吐。

### Q21 · 怎样在 Ollama 和 vLLM 之间选？

先确认部署是本机交互还是多租户并发服务。对目标模型比较易用性、可部署格式、并发调度、监控和运维成本，用真实负载验证。

### Q22 · XInference 与具体推理引擎的职责怎样区分？

区分面向调用方的模型管理、服务编排，以及实际执行模型的后端。选型时核对管理平台能否调用目标后端，以及是否暴露必要的性能参数。

### Q23 · 比较 TGI 与 vLLM 时，要对齐哪些条件？

先检查目标版本的维护状态、模型与部署支持，再统一量化、并发和生成配置，验证流式接口与错误语义，以及负载下的时延和显存。

### Q24 · llama.cpp 适合怎样的部署环境？

可在 CPU 或混合卸载等环境运行 GGUF 模型。对照本机可用内存、量化误差、不同上下文下的速度和硬件后端支持选择配置。

### Q25 · 能否给出一个按约束逐步选引擎的办法？

按硬件和模型先筛，按精度、上下文、接口再筛，接着在典型与极端流量上压测。最后把升级、监控、回滚和单请求成本计入决策。

### Q26 · 框架名单扩大后，如何按设备缩小范围？

列出实际设备、内存、可执行的模型格式及驱动，优先验收有对应后端的候选，包括端侧运行时。测真机热稳态而非只看首次生成速度。

### Q27 · 怎样评估块级草稿模型用于投机解码？

草稿端提出一段候选，目标端验证。记录每轮接受长度、草稿与验证耗时、额外显存；分别在低并发及服务稳态测每个有效 token 的成本。

## 推理优化基础

原文发布于 2026-10-19。Q1 至 Q14 依照原文编号，与推理框架专题有部分重合。[掘金题单](https://juejin.cn/post/7697515895683858451)

### Q1 · 训练系统与在线推理系统追求的指标有什么区别？

训练关心样本处理速度、达到目标质量的时间和恢复成本；在线推理还要控制请求排队、首 token 与后续 token 的时延，并应对动态并发。

### Q2 · 自回归推理的两个阶段在计算形态上有什么差异？

Prefill 可并行处理已有提示，构建各层的 KV；Decode 每一步依赖上一输出，短步反复读取权重和历史状态。瓶颈随 batch、序列长度和硬件变化。

### Q3 · 缓存过去 token 的 Key 和 Value 为什么有效？

因果注意力下过去 token 的 K/V 在后续步骤可以复用。它用随序列增长的显存，换掉重复计算历史投影的开销；新 token 仍需读取允许关注的历史 KV。

### Q4 · 怎样量化 KV cache？

选定 K/V 的精度、量化粒度及缩放元数据，写入时量化，读取时使用兼容的注意力内核。用长上下文任务检查质量，再测峰值显存和解码速度。

### Q5 · 分页注意力怎样缓解外部碎片？

逻辑 token 块按块表关联物理页，物理页可以离散分配。请求结束即可回收；页越大尾部浪费越高，过小则增加索引和调度成本。

### Q6 · INT4、INT8、FP8 的代价由什么决定？

区分权重格式、激活格式和实际累加精度。整数表示通常带缩放，浮点格式对指数和尾数作不同分配。硬件是否有匹配内核及量化误差，决定真实收益。

### Q7 · GPTQ 和 AWQ 如何分别控制权重量化误差？

GPTQ 使用校准样本估计近似二阶信息，并在逐步量化时补偿剩余权重；AWQ 利用激活统计找到敏感通道，再通过缩放减轻低比特化误差。都要在目标任务上验证。

### Q8 · FlashAttention 主要减少哪类开销？

将注意力分块，在片上计算分数并在线更新逐行归一化统计，避免把完整的分数矩阵写回再读入显存。精确注意力的主要运算量仍随序列长度平方增长。

### Q9 · 组批怎样提升吞吐，动态组批还解决什么问题？

多个请求共享一次算子调用并增加矩阵运算规模。动态组批允许每轮替换完成的请求，减少长短请求绑定；要同时限制排队时延和 KV 预算。

### Q10 · 投机解码如何兼顾速度与采样分布？

草稿端提出候选，目标端批量验证，拒绝后按相应的校正规则采样。正确实现可以维持目标分布，加速幅度取决于接受长度、草稿成本和实际并发。

### Q11 · vLLM 的块表如何参与一次解码？

调度器给序列分配缓存块，算子据逻辑位置查块表，定位历史 K/V 并写入当前 token。请求结束后回收引用，前缀共享时需正确维护引用关系。

### Q12 · 选推理运行时前应先列出哪些硬约束？

先写出模型版本、硬件后端、量化格式、目标上下文、并发及流式接口要求，用代表性请求验证输出，再以延迟目标下的吞吐和单位成本比较。

### Q13 · 如何评估 TurboQuant 之类的研究型 KV 压缩？

TurboQuant 借助随机旋转与残差估计来压缩向量并改善内积估计。评估应计算含元数据的有效位宽，在完整模型而非单个内核上比较长上下文质量、延迟和吞吐。[研究团队说明](https://research.google/blog/turboquant-redefining-ai-efficiency-with-extreme-compression/)

### Q14 · 前缀缓存与 RadixAttention 是什么关系？

前缀缓存是一种跨请求复用已有 K/V 的目标。RadixAttention 用树组织可复用前缀；命中必须对应相同 token 和兼容的模型、适配器与位置信息。

## 生产部署与模型服务

从框架与运维篇选取与模型服务直接相关的四个问题，保留原编号。原文发布于 2026-10-19。[掘金题单](https://juejin.cn/post/7697826930359877658)

### 原 Q9 · 模型应用怎样发布到生产环境？

先固定模型制品、依赖和启动参数，定义就绪条件、负载限额和失败语义。在代表性流量下验收质量与容量，再用小流量发布、错误预算和回滚开关控制变更。

### 原 Q10 · LLM 服务如何监控成本并检验优化收益？

按模型、租户、请求类型归集输入与输出 token、GPU 时间、缓存命中和失败重试。将总成本除以成功的有效业务输出，对照质量与延迟目标，避免单价下降掩盖总量扩大。

### 原 Q14 · 怎样通过后端实现 LLM 流式输出？

服务端边解码边发分帧事件，网关需关闭不必要的缓冲并处理慢客户端、心跳和取消。以首次可消费 token 的时间验收端到端延迟；断开后释放上游连接和模型资源。

### 原 Q16 · 怎样让提示词缓存稳定命中并核实收益？

把稳定、可共享的上下文放在前面，动态字段靠后；匹配按服务的实际 token 序列和模型配置判断。区分命中 token 数、计费折扣和首 token 延迟，并在租户之间设隔离边界。
