#### Q001 · 如何从执行和存储组织解释 GPU 的性能特点？

**生成参考回答（整理补充）**

GPU 以大量并行线程隐藏访存和指令延迟，线程块被调度到计算单元，warp 按 SIMT 方式执行。寄存器、共享内存、缓存和设备显存构成不同容量与带宽的层次；Tensor Core 等专用单元适合特定类型的矩阵运算。性能不是只由理论算力决定，还受访存带宽、数据复用、并行度、分支分歧和资源占用限制。回答具体 GPU 或 DCU 时应给出型号和软件栈，不能假设所有设备具有相同 warp 宽度、精度支持或互连能力；实际结论要通过目标工作负载测量。

### 02.02 · CUDA 执行与调度

#### Q002 · 多 GPU 通信中，怎样确认发送和接收缓冲区可以安全读写或复用？

**生成参考回答（整理补充）**

必须把缓冲区所有权、数据写入完成、通信完成和消费者读取完成分开定义。主机函数返回通常只说明异步操作已提交，不能据此覆盖缓冲区。生产算子和通信通过同一 stream 的顺序，或跨 stream 的 event 建立依赖；复用前再等待消费者完成。跨设备直接访问还需符合所用通信库的同步与内存可见性约定，不能只轮询普通标志位。排查时为每个缓冲区记录代次、地址和依赖事件，避免图重放使用失效地址或上一轮的数据。

#### Q003 · GPU 的 ILP 和 TLP 分别如何隐藏执行延迟？

**生成参考回答（整理补充）**

ILP 利用同一线程中互不依赖的指令，让执行单元在等待某条指令结果时处理其他工作；TLP 则利用多个可运行 warp，在部分 warp 因访存或依赖停顿时切换发射。两者互补，但都受资源限制：增加单线程独立工作常提高寄存器需求，反而可能减少同时驻留的 warp。优化应观察依赖链、可发射 warp 和实际吞吐，而不是一味追求更多线程。通过调整展开程度、每线程元素数与 block 大小，寻找寄存器压力和延迟隐藏之间的平衡。

#### Q004 · warp divergence 是什么，为什么不应把所有分支都改成无分支代码？

**生成参考回答（整理补充）**

同一 warp 的活跃线程走不同控制路径时，执行需要按掩码处理各路径，部分线程暂时不工作，可能降低有效吞吐；不同 warp 走不同分支则不直接构成这个问题。可以通过重排数据、使分支在 warp 内一致或减少昂贵路径来优化，但简单分支也可能被编译为谓词指令。强行计算两条路径再选择结果会增加计算和访存，不一定更好。现代独立线程调度也不意味着跨线程操作自动安全，仍应使用合适的同步原语，并以实际内核耗时验证。

### 02.03 · 访存与资源优化

#### Q005 · CUDA 的寄存器、共享内存和全局内存各有什么用途？

**生成参考回答（整理补充）**

寄存器主要保存线程私有的短生命周期值，访问快但容量有限，使用过多会降低驻留度或溢出；共享内存由同一 block 的线程协作使用，适合数据复用和归约，但需处理同步与 bank 冲突；全局内存容量大，延迟与带宽成本更高，应尽量合并访问。所谓 local memory 表示线程私有地址空间，不保证位于片上，寄存器溢出常落到设备内存。答题时应结合具体数据生命周期设计布局，并用编译报告和性能计数器检查实际落点。

#### Q006 · 什么是 shared memory bank conflict，怎样识别和优化？

**生成参考回答（整理补充）**

共享内存被分为多个 bank，当同一 warp 的一次访问让多个线程请求同一 bank 的不同地址时，可能需要拆成多次事务，降低有效吞吐；多线程读取同一位置的广播不能简单当作冲突。常见问题来自矩阵转置或固定步长访问，可通过 padding、改变数据布局或线程到元素的映射减少冲突。优化前先按数据类型和目标架构画出 bank 映射，再使用 profiler 验证事务和耗时，不能仅因加入一列 padding 就假定所有形状都更快。

### 02.04 · 算子实现

#### Q007 · Split-K GEMM 为什么可能破坏结果的逐位确定性？

**生成参考回答（整理补充）**

Split-K 把一次点积的 K 维拆成多份，先分别计算部分和，再归并为输出。浮点加法不满足结合律，因此改变分组或累加次序就可能改变最低有效位；如果使用竞争顺序不固定的原子累加，运行之间还可能有差异。但 Split-K 并非必然不可确定，固定分块与固定归并树可以提供受约束的确定行为。评估时区分逐位一致和容差内一致，固定精度、算法与硬件环境，同时量化额外工作区、归并开销及对路由结果的影响。

#### Q008 · Persistent GEMM 在小 M 形状下为什么可能低效，如何选择执行路径？

**生成参考回答（整理补充）**

#### Q009 · 实现 CUDA reduce 时，应怎样组织线程内、warp 内和 block 内的归约？

**生成参考回答（整理补充）**

先让每线程读取多个连续或步进元素并在寄存器中累加，再用 warp shuffle 完成 warp 内归约，把各 warp 的部分结果写入共享内存，经 block 同步后由一个 warp 收尾。跨 block 可以使用第二个 kernel 或受约束的原子累加，不能用普通 block 屏障同步全网格。必须处理不足一个 warp、非二次幂长度、空输入及掩码中的无效线程。浮点归约顺序会影响结果，应定义容差或确定性要求，并与库实现比较带宽、启动开销和边界正确性。测试时保留高精度对照。

#### Q012 · 稀疏矩阵乘向量 SpMV 应如何选择 CSR、COO 等存储方式？

#### Q013 · 如何实现并优化 RMSNorm 的 GPU 内核？

**生成参考回答（整理补充）**

#### Q014 · Online Softmax 如何在分块计算时保持数值稳定？

**生成参考回答（整理补充）**

普通稳定 Softmax 先减去最大值再计算指数和。在线版本维护已处理元素的最大值 m 与归一化和 l；新块统计为 mb、lb 时，令 m′=max(m,mb)，再令 l′=exp(m−m′)l+exp(mb−m′)lb。这样旧结果会被重新缩放到统一基准，避免指数溢出，也不必一次保留完整中间矩阵。若单独输出全部 Softmax 值，仍需缓存输入或再次读取后归一化；融合注意力时则可同时维护加权输出累加器。实现还要处理全 mask 行、归约精度及块间边界。

#### Q031 · 为什么 AdamW 训练显存常被描述为参数显存的数倍？“四倍”如何理解？

**生成参考回答（整理补充）**

必须先问清统计口径。FP32 参数与梯度各占 4P 字节，Adam 的一阶、二阶矩通常各占 4P，总计约 16P，即 FP32 参数本身的四倍；其中优化器两个矩本身是 8P，并不是优化器必然占四份参数。混合精度可能另有 FP32 主权重，状态精度、分片和低比特优化器也会改变结果。此外还要叠加激活、临时工作区和分配器保留显存。面试应先列张量、精度和份数，再估算峰值；AdamW 的解耦权重衰减并不额外要求一份完整模型状态。

#### Q038 · FlashAttention 如何避免保存完整注意力矩阵，在线 softmax 如何合并？

先从时间线找出每 token 的同步点，例如把采样结果、长度或停止标志读回 CPU 后才提交下一批工作。能在 GPU 完成的采样、轻量状态更新和张量变换尽量留在设备上，合并小传输，并用事件表达真正依赖，避免全设备同步。对形状稳定的部分可考虑 CUDA Graph 降低提交开销，但动态批次和内存地址必须符合捕获要求。最后检查流式输出所需的最小回传是否仍及时，不能用过度缓冲换取吞吐而损害用户可见延迟。

#### Q045 · GPU 池化时，MIG、时间切片和 MPS 应怎样取舍？

**生成参考回答（整理补充）**

### 10.02 · 操作系统与网络

#### Q052 · 虚拟内存解决了哪些问题，与物理内存是什么关系？

**生成参考回答（整理补充）**

进程看到的是虚拟地址空间，页表与 MMU 将其映射到物理页；这使应用无需处理物理内存是否连续，同时提供访问保护和受控共享。按需分页让尚未使用的地址不必立即占用物理内存，文件映射和写时复制也依赖这套机制。虚拟地址空间大不意味着物理内存无限，频繁缺页、换入换出或内存回收会造成延迟，超出可承受资源仍可能 OOM。排查服务内存时要区分虚拟大小、常驻集、共享页与实际分配，不能只看一个进程虚拟内存数字就判断泄漏。
