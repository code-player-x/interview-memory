面试八股文 · 长期记忆训练系统

软件设计方案 v1.0 · 2026-07-20 · 由 WorkBuddy 生成

1. 背景与目标

之前的 interview-bank-from-xhs 类 skill 把「爬题库 + 每日推送 + 判断对错 + 错题 + 邮件」全部塞进了 Agent。这带来两个问题：

  • 邮件模板漂移：回复问题的邮件模板每次都在变，不可控；
  • 强依赖 Agent：定时推送、热力图、错题本这些本不依赖 Agent 的能力，被绑死在对话循环里，脆弱且难以沉淀。

目标：把不依赖 Agent 的能力落地成一个独立软件；Agent 只保留两件最基础、最擅长的事：

  1. 爬取各平台面试八股文（生成题库）；
  2. 判断用户答案对错（LLM 判题）。

软件负责其余全部：题库管理、每日练习选题与推送、GitHub 风格热力图、错题本、艾宾浩斯遗忘曲线调度、以及固定模板的邮件发送。从而保证长期记忆真正形成。

2. 系统边界：Agent vs 软件

能力归属原因
爬取各平台（小红书/牛客/Boss 等）面试八股文Agent需要浏览器/反爬/解析等非结构化能力，Agent 最合适
判断用户答案对错（含解析）Agent需要语义理解，LLM 判题不可被规则替代
题库管理 / 导入软件结构化存储，无需 Agent
每日练习选题与推送软件按调度从题库抽题，规则化
GitHub 风格热力图软件纯前端可视化，无需 Agent
错题本软件结构化数据 + CRUD
艾宾浩斯遗忘曲线调度软件时间计算，规则化
邮件模板与发送软件模板由软件托管，固定可控，不再依赖 Agent 改写

4. 技术选型（推荐）

层选型说明
后端Python + FastAPI轻量、异步、易写定时任务；判题回调 Agent 用 HTTP
前端原生 HTML/JS 或 Vue3热力图用自绘 SVG/grid，无重依赖
数据库SQLite（→ PostgreSQL）单机够用，零运维
调度APScheduler / 系统 cron每日 09:00 跑复习邮件任务
邮件SMTP（QQ 邮箱）模板固定、由软件渲染，避免 Agent 改写
Agent 接口HTTP（REST）判题走稳定 API，降级可排队重试

5. 数据模型

questions(
  id, platform, category, difficulty,
  question_text, reference_answer,
  created_at
)

submissions(                -- 每次作答记录（热力图 & 判题来源）
  id, question_id, user_answer,
  is_correct, judge_by,        -- judge_by='agent'
  submitted_at
)

wrong_book(                 -- 错题本（由 submissions 派生 + 复习状态）
  id, question_id,
  first_wrong_at, wrong_count,
  last_user_answer,         -- 当时错答，便于对比
  mastery,                  -- 'learning' | 'reviewing' | 'mastered'
  updated_at
)

review_schedule(            -- 艾宾浩斯复习计划
  id, question_id,
  stage,                    -- 当前间隔阶梯
  next_review_at,           -- 下次应复习日期
  last_reviewed_at,
  review_count,
  status                    -- 'pending' | 'sent' | 'done'
)

activity(                   -- 热力图聚合（按天）
  day, answered, correct, wrong
)

users / settings(           -- 邮箱、间隔序列、推送时间等配置
  email, push_time, ebbinghaus_steps(json)
)

6. 核心功能设计

6.1 GitHub 风格热力图

展示「哪天回复/作答了问题」。颜色深浅 = 当天答题数量（可在 答题数 / 正确数 间切换）。数据来自 activity 表。

少 多

交互：hover 显示「日期 + 答题数」；点击某天可下钻查看当天作答的题目与对错。上图为依据样例数据渲染的原型。

6.2 错题本

字段含义
题目 / 平台 / 分类定位来源，便于按方向复习
错误日期 (first_wrong_at)首次答错时间，对应热力图坐标
错误次数 (wrong_count)多次错则加权优先推送
当时错答 (last_user_answer)记录你的错误思路，复习时对照
参考答案折叠展示，先自测再揭示
掌握状态 (mastery)标记「已掌握」可移出错题本，停止推送

列表支持筛选：按分类、按时间、仅看「待复习」。错题本与热力图联动——点开某天的错题即进入复习。

6.3 艾宾浩斯遗忘曲线 · 调度 + 邮件推送

答错 → 写入错题本 → 按间隔序列生成复习计划。到复习日，软件汇总当日待复习错题，渲染固定模板邮件推送到你邮箱。

7. 软件与 Agent 的交互协议

7.1 题库导入（Agent → 软件）

POST /api/questions/import
{
  "platform": "小红书",
  "category": "Java/并发",
  "question_text": "volatile 能保证原子性吗？",
  "reference_answer": "不能，volatile 仅保证可见性与有序性……",
  "difficulty": 2
}

7.2 判题接口（软件 → Agent）

POST /agent/judge
{
  "question_text": "...",
  "reference_answer": "...",
  "user_answer": "我认为可以保证原子性"
}
→ 200 {
  "is_correct": false,
  "explanation": "volatile 不保证复合操作原子性，例如 i++ ……"
}

降级策略：Agent 不可用时，submissions 标记为 judge_by='pending' 进入重试队列，不影响热力图与调度主流程。

8. 邮件设计（固定模板，由软件托管）

模板由软件渲染、不再依赖 Agent 改写，保证稳定可控。每日复习邮件结构：

主题：【八股文复习】今天有 N 道错题待巩固（2026-07-20）
────────────────────────
早上好 👋 根据艾宾浩斯遗忘曲线，今天有 N 道题到了复习时间：

1. [Java/并发] volatile 能保证原子性吗？
   · 你曾答错：我认为可以保证原子性
   · 参考答案（点开查看）：volatile 仅保证可见性与有序性，不保证原子性……
   · 上次错误：2026-07-13 · 已错 2 次

2. ...

────────────────────────
💡 先凭记忆作答，再点开参考答案对照。
✅ 记住了 → 回复「1 记住」推进间隔；❌ 还没记住 → 回复「1 没记住」提前再次推送。
📊 查看你的热力图：<链接>

模板内变量仅：日期、待复习列表、错题历史、热力图链接。结构固定，不会随对话漂移。

11. 风险与备注

  • Agent 判题稳定性：用稳定 HTTP 接口 + 重试队列，避免阻塞主流程。
  • 邮件送达：QQ 邮箱需开启 SMTP 且用授权码；模板固定后无需再改。
  • 题库来源合规：爬取各平台需遵守 robots 与平台条款，仅作个人学习用途。
  • 长期记忆验证：热力图 + 错题本 + 间隔推送三者闭环，即可观测记忆形成过程。
